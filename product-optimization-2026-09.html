Grandettoken 产品优化需求报告

2026-09-18 · 基于 v0.1.8 现状 · 依据:代码盘点 + 本会话用户反馈轨迹(看不清/折叠错位/消耗「——」/退款疑问/周期倒计时)

一、现状盘点:产品已经具备什么

能力现状
渠道覆盖6 个:4SAPI(申请制)、OpenCode Go(配额三窗)、DeepSeek / Hapi(充值推算)、Trae / WorkBuddy(积分+逐笔到期,复用本机登录态)
展示形态面板 / 紧凑条 / 胶囊 / 贴边吸附;字号三档;高对比配色;渠道显隐(隐藏即停取数)
数据能力SQLite 快照 90 天;消耗差值推算;申请制倒计时 + 缺口预警;积分到期表;OpenCode 重置倒计时;自动更新链路完整
交互行点开详情 + 迷你柱图;设置页四页签;托盘菜单;胶囊轮播
已知欠账(代码实证):配置里的 notify、collapseOnBlur 是死字段(有存储、无 UI、无消费方);取数为串行(6 渠道最坏 4×8s);消耗全靠快照差值推算,关机时段必有空洞。

二、机会地图(影响 × 成本)

速赢:高影响 × 低成本(先做)

  • A1 通知系统落地(把死掉的 notify 做实)
  • A2 「可申请了」日历提醒
  • C4 一键打开渠道控制台
  • D1 取数并行化

主力:高影响 × 中成本

  • B1 接流水接口,消耗从「推算」变「精确」
  • B2 余额趋势曲线(数据已在库里)
  • A3 到期/限流主动提醒
  • C1 隐私模式(一键遮数)
  • C3 全局快捷键

顺手:中影响 × 低成本

  • C2 失焦自动收起(做实或删掉死配置)
  • B3 快照 CSV 导出 / 配置迁移
  • D2 死配置清理

暂缓:低影响或高成本

  • E2 用户自定义渠道(表单+鉴权太重)
  • 主题商店、多语言、移动端
  • E1 渠道扩展 → 按需排期(见路线图)

三、需求详单

A · 提醒系统 —— 挂件从「你看它」变成「它找你」

P0A1 系统通知总框架 成本 S
接入 tauri-plugin-notification,定义四类事件:余额跌破红线 / 已限流 / 积分将过期(≤7天)/ 可申请额度。带节流(同类 24h 最多一次,避免轰炸)。
证据:config.notify 字段从 v0.1.0 就存在但全链路无人消费——用户勾了开关什么也不会发生,属于「承诺未兑现」。
P0A2 申请日历提醒(4SAPI 类) 成本 S
claim.daysUntilEligible 归零时推一条「4SAPI 现在可申请 ¥200」;错过一次申请 = 真实断粮风险,这是全产品价值最高的一条通知。
数据现成:claim 状态每轮已算好,只差发通知。
P1A3 到期 / 限流提醒 成本 S
Trae/WorkBuddy 积分 7 天内到期(过期即损失)、OpenCode 触发限流时通知。节流同 A1。

B · 数据可信度 —— 「推算」标签是现在的天花板

P1B1 接流水接口,精确消耗 成本 M
4SAPI(new-api 系)有 /api/log/self 消费流水;接入后今日/本周/本月消耗从「快照差值推算」变「按请求逐笔求和」,关机时段不再漏记,「推算」标签可摘。
证据:本会话两次用户疑问(「今日消耗对不上」「本周为什么是——」)根因都是推算空洞;快照库 9-16 才有数据是极端例子,但空洞天天存在。
P1B2 余额趋势曲线 成本 S
详情区加一条 30 天余额折线(数据已在 snapshots 表),充值/申请点标 ▲、消耗段自然下行——一眼看出「这钱是怎么花掉的」,也是排查退款类疑问(见 4SAPI 那次)的自助工具。

数据现成;现有迷你柱图只画消耗,看不出余额水位。
P2B3 数据导出与迁移 成本 S
快照 CSV 导出(自用分析)+ 配置 JSON 导出/导入(换机迁移;密钥仍在凭据管理器,导出文件不含密钥)。

C · 挂件体验 —— 常驻桌面的分寸感

P1C1 隐私模式(一键遮数) 成本 S
余额/积分是敏感信息,挂件常驻办公桌面。快捷键或托盘菜单切换「遮罩态」:数值变 ¥•••,胶囊只显示渠道色点。再配合 A1,通知文案也不带具体金额。
动机:产品定位就是「桌面上摆着余额」,现在没有任何遮挡手段。
P1C3 全局快捷键 成本 M
tauri-plugin-global-shortcut:默认 Alt+G 展开/收起面板、Alt+Shift+G 隐私模式。挂件核心动作不该只有鼠标路径。
P2C2 失焦自动收起(做实或删除) 成本 S
面板点开、处理完事、点别处 → 自动收成紧凑条。collapseOnBlur 字段同样从 v0.1.0 死到现在:要么实现,要么删——留着就是骗设置。
P0C4 一键打开渠道控制台 成本 XS
渠道行右键/详情区加「打开账单页」:tauri-plugin-opener 已装,每个渠道 URL 已在定义里,纯接线活。看到异常→去平台核对的路径从手输网址变成一次点击。

D · 工程与扩展

P1D1 取数并行化 成本 S
6 渠道串行 await,一个入口挂着全轮变慢(最坏 4 入口×8s/渠道)。改 futures::join_all 并发,单轮最坏从 ~2 分钟压到 ~8 秒,也降低面板首开空窗。
证据:fetch.rs:618 逐渠道 for-await。
P1E1 渠道扩展(按需) 成本 S/渠道
架构上「加渠道 = 一条定义 + 一个 extractor」,扩展边际成本低。候选按公开接口友好度排:OpenRouter(credits API 最简单)、Moonshot/硅基流动(余额 API 公开)、Kimi/智谱。建议每版 +1~2 个,顺带收集用户想接的渠道。
P2D2 死配置清理 成本 XS
A1/C2 落地后,把仍未消费的字段(如 sort 之外的遗留)清干净,防「设置页有开关但没行为」再次发生。

四、建议路线图

v0.2.0「它会主动找你」
  • A1 通知框架 + A2 申请日历 + A3 到期/限流
  • C4 控制台直达
  • D1 取数并行
全部是数据现成、只差接线的小件,一次发完产品气质就变。
v0.2.1「数字可信」
  • B1 流水精确消耗(4SAPI 先行,模式跑通后推给 DeepSeek 等有流水的平台)
  • B2 余额趋势曲线
  • C1 隐私模式 + C3 全局快捷键
v0.3.0「更多平台」
  • E1 渠道扩展 ×2~3(OpenRouter 优先)
  • B3 导出/迁移、C2 收尾
