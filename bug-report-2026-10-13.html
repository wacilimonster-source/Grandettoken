C. 走查当场抓出的三个新缺陷(都已修)

条目现象 → 根因 → 处置
R-1 写入预告竞态
实机抓到		点模型卡上的客户端徽标 → 弹层显示「正在生成写入预告…」→ 期间按 Esc → 控制台抛 TypeError: Cannot set properties of null (setting 'error')(openModelSheet)。根因:预告要读客户端配置,耗时 1~2 秒;await 回来后代码又去取一次全局 MDL.sheet,而 Esc/点遮罩已经把它置成 null —— 第十三节给 Esc 链加的"先关弹层"恰好把这条路径变得可达。处置:弹层对象先存进局部变量,回来时判 MDL.sheet !== sheet 就作废,不再往已废弃的弹层落账,也不重画。
R-2 saveCfg 的回滚是假的
顺藤摸到		修 R-1 时顺手读第十三节写的 P2-32 修复,发现 const backup = CFG 存的是引用:调用方全是原地改 CFG.sort = …、pillChannels.splice(…),失败时 CFG = backup 回去的还是改过的那个对象。表现是"提示保存失败,但界面仍显示新值,重启后悄悄变回去"。处置:快照改成深拷贝(JSON.parse(JSON.stringify(CFG))),注释里写明为什么必须是拷贝。saveConfigAndRefresh 那条不受影响(它失败后靠 refresh() 从后端取回真值)。
R-3 launch-debug.ps1 单候选时自毁第一次想启动成品 exe 时脚本直接抛「no app binary found」,而 exe 明明在。根因:PowerShell 管道只匹配到一个候选时会塌成字符串,于是 $cands[0] 取到的是路径的第一个字符 'G' —— 之前一直没暴露是因为目录里同时有 tokenscope.exe 和 Grandettoken.exe 两个候选(数组形态正常);这轮只有改名后的那一个。处置:外面套 @() 强制成数组、判 .Count。这条属于第十三节 G-3 的同类(挑二进制的分支自己会坏),已一并修掉。
