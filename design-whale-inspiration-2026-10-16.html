1. 先说人话

小鲸鱼（dsh-whale-widget）是 DeepSeek Harness（DSH，DeepSeek 官方那套带插件系统的 AI 工作台）上的一个社区挂件:界面右下角一只会拖、会弹、会叫的小鲸鱼，气泡里显示 DeepSeek 余额、今日已用、每轮对话花了多少，还管预警、今日预算，并且支持接 34 种第三方服务的余额查询。它和我们做的，本质是同一种东西 —— 一个常驻桌面的「钱袋子仪表」。

为什么拿它当镜子照:① 同一条赛道:它也把「余额下降 = 消费、上升 = 充值」的观测记账做成了内核，而且做得比我们深；② 同一种架构:本地文件 + 定时轮询 + 系统凭据服务，跟 Grandettoken 一个路数，经验可以直接搬；③ 它是活的:内部构建代次写到 v789、代码注释里回指到 issue #232 —— 每个功能都被真实用户锤过，能上它的功能清单就等于拿到了一份「验证过的答案」。

结论先给:值得我们抄的核心不是「让它变可爱」，而是三件严肃的事 —— 数字的诚实性（说清楚哪些数字有缺口）、提醒的克制（跌破才响、一天一次、成功静默）、渠道的可持续（模板化自定义 + 一键体检）。可爱（按压、冒泡、两声提示音）只是顺路捡的，排最后一个包。

3. 它最值钱的三段设计（记账内核）

读的是 lib/accounting.mjs，289 行；下面每段都从原文来。

3.1 开头第一句注释，就是它的立场

原文（首行）:Balance observations are not a transaction API. Keep them separate from token estimates and require explicit credits/debits for reconciliation. 翻译:「余额观测不是交易流水。把它和 token 估算严格分开，校正时必须让用户显式填『到账』和『其它扣减』。」金额全程用 8 位小数的定点整数算（SCALE = 100000000），不碰浮点。

对照我们:我们已有「消耗是推算值 + clamp + 标注『推算』」的口径（DESIGN 7.3），立场一致。它比我们多出来的，是下面两个具体机制。

3.2 缺口判据:「这天数字是全的吗」是一等公民

它的判据带具体数字:观测起点距当天 00:00 超过 10 分钟，或（对已经过去的天）最后一次观测距次日 00:00 超过 10 分钟，这一天就标「部分数据」，并给出「从几点开始才有观测 / 观测到几点为止」。背景装在代码注释里（issue #184）:以前「今日已用」长期偏小，界面上没有任何『这是部分数据』的提示 —— 用户以为花了 10 块，其实只观测了半天的 10 块。

对照我们:快照推算同样有「程序没开 = 数据空洞」的问题，现在我们只写「推算」两个字。缺的具体是「缺在哪一段」。

3.3 换 key 分账本:数据没丢，只是没有入口能再看到它

它的实现:余额账本按「凭据指纹 + 币种」分本，换 / 删 API key 就开一本新账；但展示侧跨本聚合——当前本是主行，别的本标注「历史账户」仍列出来。代码注释（issue #163）写得很直白:「数据没丢，只是没有任何入口能再看到它」。导火索是:换 key 后旧数据退化成「本地估算 ¥0.00」，用户以为账丢了。

对照我们:快照按渠道存，不认 key。换了 key（同一家服务商换账号、换中转 key），新旧两个账户的余额差会直接进消耗推算 —— 换到余额更高的号是一笔假充值（clamp 掉，无害），换到更低的是一笔假消耗。

4. 启发一 · 信任包（建议 v0.1.35）

主题一句话:给每个数字上「溯源章」。三件:缺口标注、渠道体检、变动台账。

4.1 观测缺口标注

柱图里带斜纹的两天 = 当天有大段没开机，数字只算了一半 —— 鼠标悬停告诉你「覆盖 10:23–23:59」。

  • 怎么落:行详情的今日/本周/本月消耗旁标一行「数据自 X 起」；仅当缺口 ≥ 10 分钟才出现（正常开机不会天天挂一行字）；过去的日子点开柱图能看到当天覆盖区间。
  • 依据:它用「10 分钟」卡误报线，原话是「正常运行时两个缺口都只有几分钟，不会误伤正常日」。
  • 数据从哪来:只用现有的快照表（最早/最晚一条快照时间），不新增任何请求。
  • 顺带:汇总条 hover 提示「今日合计包含 1 个渠道的部分数据」。
三问 用户可感知:今天数字为什么偏小，第一次有了答案；环比「昨天 +30%」不再莫名其妙。
风险与对策:空隙阈值卡太紧会天天挂提示 —— 用 10 分钟起步、只在真缺时出现；文案统一「数据自 X 起」。
不做的后果:永久只能靠「推算」两个字让用户自己猜；长期下来用户会不信任整块数字。

4.2 渠道体检（每渠道「测试连接」+ 一键体检报告）

它对应的是两样:每个模型都有「测试连通性」按钮（先验证 key 再用）；README 里教用户「两半区自检」（宿主半区看某文件、客户端半区看某存储键，各自证明一半管道是活的）。我们的对应缺口:PROGRESS.md 里「系统代理那条仍未取证」、以及排障全靠 launch-debug.ps1 落日志人肉看。

可点着看（演示数据）:设置与管理 → 关于 → 运行体检 




三问
用户可感知:「为什么这块数字不对」从玄学变成一张清单；每个渠道卡多一个「测试」小按钮，配新 key 前先验一遍。

风险与对策:测试 = 真发一次请求（复用现有取数链路，不新增接口种族）；报告里只出现「用什么域名、拿到什么数、错误分类」，永不出现明文密钥（沿用现有密钥纪律）。

不做的后果:每次异常都靠开日志 / 跑脚本；「系统代理有没有干扰取数」这类问题一直没有产品内出口。

6. 启发三 · 拓展包（建议 v0.1.37）


主题一句话:让「再连一家」不再等于「等我们发版」。



6.1 自定义渠道:先做「中转站」，再做「全自定义」


小鲸鱼的这套是它产品面最宽的部分:34 个厂商模板（选完自动带好凭据名/币种/接口/字段路径/探活地址；留空 = 沿用模板默认值）、全手填档（URL 与字段路径自己写，支持 a.b[0].c 与倍率）、探活档（官方没有余额接口的 20 家：验证 key 可达即可，余额显示「—」）。它的两条原则我们要原样学:


    
  
  • 模板只提供默认值 —— 厂商接口变了，用户自己改字段路径就能自救，不用等作者发版；
    • 
  
  • 保存前先「测试连通性」 —— 坏配置进不来（和我们 4.1 的体检是同一个按钮的两种场景）。
    • 




  
期做什么用户得到什么

  
一期新增一类渠道「OpenAI 兼容中转站」（OneAPI / New API 那批）:填地址 + key，内置探法；测试通过才落库、出现在渠道列表（可设简称与颜色）常跑的中转站不再受 7 渠道限制;消耗推算自动适用（快照差法是通用机制，不需要为新渠道写任何核算代码）

  
二期全自定义 HTTP:URL / 方法 / 字段路径 / 换算倍率；外加「探活模式」（只验 key，余额显示「—」，不参与消耗合计）接口变动时用户可自救;非常规服务也能挂上来「至少看着它活着」




三问
用户可感知:多一个「添加自定义渠道」入口；中转站换家、上新的号，不用回来找我改代码。

风险与对策:① 模板维护面变大 —— 对策是「默认值 + 用户可覆盖」的它式设计，测试按钮挡在保存前；② 密钥发往用户自填域名 —— 只发往用户自己填的地址，密钥仍只进 Windows 凭据管理器（零信任纪律不变），保存前界面明示「请求将发往该地址」。

不做的后果:每来一家新服务商都要走一遍「调研接口 → 改代码 → 发版」；这类需求会越来越频繁（中转站是最常换的一环）。

与《明确不做》核对（DESIGN 1.4）:不冲突 —— 仍是纯只读账务，不发任何写请求到平台；不做汇率（倍率由用户按 ¥ 口径填）；单机单用户不变。

7.2 音效两声:签到结果 + 跌破红线


    
  
  • 它怎么做的:一整套（按压/松开/每轮/提问/授权五类事件、自定义音效组、逐事件音量、试听、保存才生效）—— 这套我们不学（见第 9 节）。
    • 
  
  • 怎么落:只做两声且默认关:① 签到成功「叮」一下（自动化跑在后台时，这一声就是「今天领到了」的收据）；② 跌破红线时一声警示（与 5.1 的通知同一时机、同一个开关的姊妹项）。
    • 
  
  • 三问:可感知 —— 后台行为有了即时反馈；风险 —— 声音天然扰人，对策是只有两处、默认关、音量跟随系统；不做 —— 纯加分项。

8. 散件四件（随包捎带，不单独发版）



  
#散件来源与做法推荐

  
S1换密钥账目隔离（第 3.3 节的落地）快照按「密钥指纹」分段:换 key 起新基线，不跨账户推算消耗；旧段标「历史账户」仍可看。指纹 = 取到 key 后哈希，明文仍只在凭据管理器做。否则换一次号就凭空一笔「消耗」

  
S2长期趋势（90 天明细 → 365 天日级）学它「明细压日级、归档独立文件、主库不膨胀」:90 天前的快照压成每日一条摘要保留一年；行详情柱图加「近 3 月 / 近 12 月」切换。只展示不导出（维持非目标）可做。数据本来就在，只是活得久一点

  
S3「真 0」与「没数」全面审查学它「取不到显示 —，真的为 0 才显示 0.00」:全局过一遍每处数字；余额真 0.00 是最高级警报，应直接进 5.1 通知路径做。审查类，改的是文案与判断

  
S4设置保存语义审查学它「面板内改动只落内存，点保存才生效；取消完整还原；连『恢复默认』也能撤销」:把我们设置页每个开关过一遍「立即生效 vs 显式保存」的语义，不齐的拉齐做。审查类，不动界面





9. 劝退清单（明确不学）



  
不学为什么

  
气泡编辑器全家桶（点击序列 / 加权随机 / 模块库 / 拖拽排版）它是聊天伴生品:每轮对话结束需要一个「说话」的出口。我们没有对话流，做出来全是维护成本（它前端 2.2 万行，一多半在这）

  
全事件音效矩阵（五类事件 × 自定义音效组 × 逐事件音量）我们只留两声（7.2）；音效组编辑对 7 渠道的账本工具是纯负担

  
移动端触控适配Windows 桌面挂件，不解释

  
34 家模板全量铺开它的大多数模板是「无余额接口 + 探活」，那是「装了 34 家服务」的用户画像；我们起步只做中转站一类（6.1），按需加

  
按 token 估算消耗（读本机会话日志凑数字）我们已有更准的「余额观测」口径；两套口径并存会打架（它的校正流程一半复杂度就是用来缝这个）

  
角色 / 音频 / 图片资源管理窗口除非哪天真有「自定义胶囊形象」，否则不建资源管理器





10. 它的工程习惯（抄作业，不用裁决）


    
  
  • 带数字的判据:「缺口 > 10 分钟算部分数据」这种线，写成常量 + 注释，界面才敢跟用户解释。我们的阈值也该这么写（标黄/标红已是）。
    • 
  
  • 新功能默认关、且写明关掉的后果:它给签到/扫描都写了「关掉后一个请求都不发」；我们签到的空态文案已经是这个路数，继续沿用。
    • 
  
  • README 里教用户自检:「看这两个文件/存储键，就知道它有没有在跑」—— 配 4.2 的体检，我们把「装了之后怀疑它没动」的问题一次性答掉。
    • 
  
  • issue 编号进代码注释:它 232 个 issue 的回查成本极低（// v789（issue #184）：…）。我们用 PROGRESS.md 做同一件事，保持。
    • 
  
  • 素材来源声明:它把「代码 MIT、素材 as-is、出处不可考就如实写、有主张就换」做成了 PROVENANCE 文件。我们发公开仓库，早晚需要这一页 —— 记一笔，不急着做。
    •
