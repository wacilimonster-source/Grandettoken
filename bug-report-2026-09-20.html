P2 #1更新覆盖层样式作用域错位:长说明把「立即更新」推出窗口,换行全被折叠

app/src/styles.css:277-281 · app/src/index.html:45-49 · app/src/styles.css:77-80

覆盖层(标题旁更新标签点开的那个)里的 .uhead / .unotes / .ubar 是唯一样式规则,却写死在 .upcard 作用域下 —— 而覆盖层的 DOM 根本没有 .upcard 祖先(管理页卡片才有),三条规则一条都不命中:

styles.css:277  .upcard .uhead { … }        /* 覆盖层里没有 .upcard 祖先 → 不命中 */
styles.css:278  .upcard .unotes { … white-space:pre-line; max-height:…; overflow-y:auto }
styles.css:280  .upcard .ubar  { … }

同时 .upd-ov 是 top/bottom 固定盒,根元素 overflow:hidden,.upd-ov-in 自身没有任何 max-height / 滚动约束。

运行时实测(v0.1.13 真机,CDP 注入真实长度的更新说明): ① 15 行 / 640 字(与本项目历次发版同级):按钮仍在窗口内(bottom 374px < 560px),但 white-space = normal —— 说明里的换行全部被折叠,段落挤成一团;② 30 行 / 1,100 字(大版本完整 changelog 的量级):卡片高 820px > 窗口 560px,elementFromPoint 打不到「立即更新」按钮 (goHitTest: false)—— 按钮被推出窗口,不可点。

影响(修复前)

  • 凡是带换行的更新说明,覆盖层里必然排版错乱(换行折叠),与管理页卡片(正常 pre-line)呈现不一致;
  • 说明一长(大版本真实 changelog 的量级),「立即更新 / 跳过此版本 / 稍后」三个按钮整体被推出窗口可视区且窗口不可滚动 —— 更新流程在覆盖层里走不下去,看起来像"点了没反应",用户只能自己去设置页找入口;
  • #ovVer/#ovDate 的 flex 排版、#ovBar 的边距同样退化。

修复后效果

说明按原始换行分节展示(与管理页一致);超长时说明区内部滚动(max-height + overflow-y:auto), 三个按钮始终钉在可视区内可点 —— 任意长度的 release notes 都能直接在覆盖层完成升级,不再有"按钮消失"这条路。

建议:三条选择器改成 .upcard .uhead, .upd-ov .uhead { … }(unotes / ubar 同理),并给 .upd-ov .unotes 补 max-height + overflow-y:auto(或让 .upd-ov-in 自身限高滚动)。
