一、看不清的根因(先诊断再开方)

  • 次要文字用了低对比色:--tx3:#646d80 在 #12141a 上对比度仅 3.6:1,低于 WCAG AA 小字号要求的 4.5:1 —— 而副标题、说明、日期、底栏全是它;
  • 字号下限太低:10 / 10.5px 出现在标题栏按钮、汇总标签、到期角标等 12 处,中文在 11px 以下笔画开始糊;
  • 状态色没为小字号调亮:--bad:#f0554d(5.4:1)用在 11px 文字上偏暗,--ac:#5b8cff 同理。
→ 方案:字号做成 4 档可设置(紧凑/标准/大字/特大,走 CSS 变量倍率,设置页里选);色值整体提亮次要层并把全库字号下限抬到 11.5px。两者互不干扰、可叠加。

字号档位怎么生效(实现草案,确认设计后再动代码)

  • 配置新增 fontScale: "sm"|"md"|"lg"|"xl"(默认 md),设置页「显示」区加一排分段按钮,即点即生效;
  • styles.css 全部 font-size/padding/gap/图标尺寸 改为 calc(Npx * var(--u)),--u 由档位给 0.92 / 1 / 1.15 / 1.3;全库字号下限 max(11.5px, …) 兜底;
  • app.js 的 SIZES 乘以同一倍率(面板 380×560 → 380×644;紧凑条/胶囊高 46 → 53/60),fitPill 量宽逻辑不变;
  • 备选实现:Tauri webview.setZoom() 整窗缩放 —— 改动最小,但窗口尺寸仍要手动 ×倍率,且位图图标会发虚,故推荐 CSS 倍率方案。

「优化色值」开关只换 :root 里 8 个变量,不动任何布局 —— 也可以做成设置项「高对比配色」与现有配色并存,由你定(见下方裁决项)。

四、待你裁决的三点

  • ① 字号档位数量:四档(紧凑/标准/大字/特大)还是三档(标准/大/特大)?—— 现状已经偏小,「紧凑」档实际是 12px 基线,可能没人用;
  • ② 色值策略:A. 直接替换现有配色(所有人受益,无开关);B. 做成「高对比配色」开关默认关;C. 直接替换 + 保留开关可切回旧色。推荐 C→A 两步走:先替换,若有人反馈太亮再加开关;
  • ③ 折叠形态要不要跟随字号:紧凑条/胶囊高度随倍率长(46→53/60)会改变贴边吸附的观感;也可以折叠形态固定标准字号、只有面板跟随。推荐跟随(信息一致性)。
