一、结论速览

  • 本机已实测本机验证:你机器上有 Codex CLI 的 ChatGPT 登录态(~/.codex/auth.json,今天 02:43 刚刷新过),读凭据这一步零障碍;
  • 用量数字不在本地文件里 —— auth.json 只有 token,没有任何额度数据。余量必须拿 token 查 ChatGPT 后端接口 wham/usage(Codex CLI 自己每 60 秒就轮询这个接口拿限额信息,我们做的是同一件事的只读版);
  • 形态对齐现有「配额型」渠道,但窗口长度随套餐变实测:接口返回 rate_limit.primary_window(+ 可选 secondary_window)。你这台 free 计划实测是单个 30 天窗、used_percent=0;Plus/Pro 预期才是「5 小时 + 每周」双窗(需付费账号实抓确认)。无论几窗、窗长多少,都映射到现成的 Window{label,remainPercent,resetsAt} —— 大数字、迷你条、倒计时、组合预警全部复用,标签按时长自动生成;
  • 两个硬前提:①网络 —— 本机 shell 直连 chatgpt.com 超时(你的 CLI 能通说明走的是系统代理/TUN,应用侧 reqwest 必须显式跟随系统代理,否则装上也是「取数失败」);②套餐 —— 本机账号 plan_type=free,Codex 免费额度极小甚至为零,接口大概率返回空/打满,建议用 Plus/Pro 账号验证;
  • 工作量估计:1~2 天(appauth 加一个读取器 + provider 定义 + 复用配额型渲染 + 代理适配 + 测试),不需要新依赖。

  • 只读、不刷新、不回写 —— 与 Trae/WorkBuddy 同一铁律:ChatGPT OAuth 刷新会轮换 refresh_token 并作废旧的,我们刷一次就把用户 CLI 踢下线一次。token 过期就如实提示「打开 Codex CLI 随便跑一句重新登录」;

三、用量接口

  • 端点:GET https://chatgpt.com/backend-api/wham/usage来源佐证 —— Codex CLI 内置轮询器每 60s 打它(开源仓库 issue 里可查证),返回的 rate_limit 就是 CLI 弹「额度已用完,xx 后重置」提示的数据源;
  • 请求头:Authorization: Bearer <access_token> + ChatGPT-Account-ID: <account_id> + 常规浏览器/CLI User-Agent;
  • 响应形状经代理实抓,HTTP 200:核心是 rate_limit.primary_window 与 rate_limit.secondary_window(可空),各含 used_percent(已用%)、limit_window_seconds(窗长)、reset_after_seconds、reset_at(unix 秒);另有 rate_limit.allowed/limit_reached、credits.balance(按量付费余额,订阅号为 null)、plan_type。映射:remainPercent = 100 - used_percent、resetsAt = reset_at、窗标签按 limit_window_seconds 生成(≤6h→「5 小时」、≤8d→「每周」、≤35d→「每月」);
  • 本机实测:走你的代理 127.0.0.1:7897 直连成功(HTTP 200,941 字节,见第七节响应)。free 计划只有单个 30 天窗、used_percent=0、secondary_window=null —— 即「本月额度」型,而非 5 小时型;付费计划的窗口结构仍建议实抓一次。

五、风险与合规(诚实清单)

  • 非公开接口:wham/usage 是 ChatGPT 后端内部 API,字段可能随时变、也可能哪天加 Cloudflare 盾 —— 和 WorkBuddy 逆向接口同级的风险,我们的失败降级(沿用上次快照+标注)正好兜住;
  • ToS 灰度:拿 CLI 的会话 token 查自己的用量,行为与 CLI 本身一致、只读、低频(60s 轮询池,不比 CLI 更频繁)—— 但严格说属于「非官方客户端使用会话凭据」,自用无碍,不适合写进公开宣传;
  • 代理依赖:没有代理/梯子的环境这个渠道永远「失联」—— UI 上要说人话(错误文案:「需要能访问 chatgpt.com 的网络环境」);
  • free 计划噪声:免费额度极小,可能常年 100% 或空数据,预警会一直亮 —— 属数据本身如此,不是 bug;
  • 过期体验:access_token 10 天有效,但只要你日常用 CLI 它就自动续;长期不用 CLI 后过期 → 界面提示「打开 Codex 重新登录一次」,与 Trae 的体验一致。

六、备选路线(不推荐但记录)

  • 官方 Usage API(api.openai.com/v1/usage):只覆盖 API Key 计费模式(按 token 付费的开发者),ChatGPT 订阅的 Codex 额度它查不到。若哪天你用 auth_mode=apikey 登 CLI,可以做成第 7 个「Key 型」渠道,和 4SAPI 同类;
  • 解析 CLI 本地日志/会话文件:codex 的 rollout 日志里有 token 计数,但那是「消耗量」不是「限额余量」,口径不对,放弃;
  • 让用户手填 Key:兜底方案,失去「零配置」的灵魂,不建议。
