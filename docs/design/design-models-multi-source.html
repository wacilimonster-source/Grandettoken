2026-10-13 · 产品设计（未写代码）。接口事实全部来自本机实测，可复核；UI 原型是静态稿，尺寸与真机一致（380 宽）。
这一轮要解决的

① Hapi 也能看模型、也能配到客户端;② OpenCode Go 同样; ③ 写入/取消写入的确认框从列表底部挪到弹层(现在要点完滚到底才看得见,体验差); ④ 模型列表按价格由高到低排。

其中 ① ② 需要把模型页从「4SAPI 专用」改成多来源 —— 这是本轮唯一的结构性改动,其余三条都是它之上或独立的小改。

取证结论:两条新来源都能列模型(Hapi 需密钥、Go 公开);但价格只有 4SAPI 有 —— Hapi 没有公开价目表,Go 是订阅制不按 token 计价。第 ④ 条因此要分来源说明(见第五节)。

说人话版结论

① 两条来源都能列模型,而且比预想的好拿。OpenCode Go 的 /zen/go/v1/models 公开(实测 200,38 个模型,不用密钥);Hapi 的 /v1/models 存在但要密钥(实测 401, 错误体明说要 Bearer / x-api-key)。Hapi 那个站不是 new-api,/api/pricing 是 404 —— 它没有公开价目表。

② 「价格由高到低」只有 4SAPI 能严格做到。4SAPI 有价目表(160 个模型,倍率齐全); Hapi 的价目表在它自己控制台的接口里(/api/v1/groups/rates,实测 401 —— 认的是登录态, 认不认 API key 待实现期用你的密钥试一次);OpenCode Go 是订阅制(按 5 小时/周/周期限流), 根本不按 token 计价,给它编个"单价"就是撒谎。所以:有价格的按价格降序,没价格的整体排在末尾并标明原因。

③ 写入确认改成弹层,位置固定不用滚。现在那块确认面板长在列表末尾,点完行内小按钮 还得滚到底才看得见 —— 这也是你说的"体验不好"。改成复用「更新提示」那套覆盖层:标题写清 模型 → 客户端,内容可滚,按钮固定在底部,关闭即回到原位置。

④ 一个坑要提前说:同一个模型名可能同时存在于多个来源。比如 gpt-6-luna 在 4SAPI、Hapi、Go 里都有。现在"已配置"的判定只认 4SAPI 的域名,多来源之后必须按来源分别判定 (客户端条目里的 url 决定它来自哪个来源) —— 否则会出现"在 Hapi 页显示已配置,其实配的是 4SAPI"这种假绿。

弹层的规矩

  • 标题永远是「模型 → 客户端」,关闭按钮在右上;点遮罩不关(避免误触丢确认上下文)。
  • 按钮固定在底部,内容区自己滚 —— 预告再长也不会把按钮挤出屏幕。
  • 已配置时给两条动作:「取消写入(移除这条)」(danger)与「重新写入」;未配置时只有「写入」。
  • 阻塞原因(目标在跑 / 结构不认识 / 没配密钥)写在按钮正上方,确认按钮置灰。
  • 写完在同一个弹层里出结果 + 备份路径 + 回滚入口;关闭即回到列表原位置(滚动位置不跳)。
  • Esc 关闭;打开弹层时列表不再接收点击(遮罩挡住)。

四、排序与价格口径

来源排序价格显示为什么
4SAPI单价降序(高 → 低)入/出 ¥/百万 token有站点价目表;最烧钱的排最前,和"哪个会先没钱"是同一眼
Hapi无价格 → 排在末尾,内部按「已配置优先 + 名称」不显示价格行站点没有公开价目表;实现期先用你的密钥试一次它控制台的价目接口,认就显示、不认就留空
OpenCode Go无价格 → 排在末尾,内部按「已配置优先 + 名称」不显示价格行,口径行注明「订阅制,不按 token 计价」订阅制按 5 小时/周/周期限流,给模型编一个"单价"就是撒谎

不变量(沿用前几轮的口径纪律):价格只从站点声明里来,没拿到就不显示、不折算、不猜; 不可用(不符合"能用上的"规则)的行永远不出现;同一个来源内,单价相同的按名称排,保证顺序稳定可复现。

9.2 与设计稿的偏差

项设计稿实现原因
来源芯片的模型数芯片上写"该来源的模型数"写,但只有取过的来源才有数字,没取过的写 —不为了显示一个数字去请求另一个来源(切过去才取)
已配置的显示行内绿色徽标徽标 + 保留绿色描边(原来的 .done 样式)徽标管"是什么",描边帮扫视;两者都在,成本为零
ZCode 的 provider没写每个来源一个 provider,名字用来源名(4SAPI / Hapi / OpenCode Go)不然三家会互相覆盖同一个 provider
「不可用」徽标只留标记一样;并额外在"可用集合没取到"时说明只列已配置的与 v0.1.23 的规则一致
