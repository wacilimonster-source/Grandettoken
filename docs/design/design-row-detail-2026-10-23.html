首页渠道展开区 · 产品设计

2026-10-23 · 依据 v0.1.61(6630600)代码实读 + 无头 Edge 实测 · 本文只做设计,未改动任何代码

0. 结论

需求两件事:① 删掉渠道行点开后的日期区间筛选(近 24 小时 / 7 天 / 30 天 / 3 月 / 12 月)和迷你柱图; ② 把所有渠道的展开交互与展示形式调成一套。

只删这两样不够。它俩本身 53px(连外边距约 71px),而实测一张展开的金额型卡整行 691px, 是列表可视高(413px)的 1.7 倍 —— 点开任何一行,其余渠道全部被挤出屏外;删完它俩仍有约 620px。 占地的大头是 12 条「最近变动」(350px)和积分「逐笔到期」表(168px),再加上同一份列表在行头和详情里各画一次。

建议的方案:

  1. 删:区间按钮、迷你柱图、两句只为柱图存在的说明、后端 get_series 命令。变动台账、今日/本周/本月、365 天日级归档都不动。
  2. 一套骨架:所有渠道的展开区按固定顺序画五段 —— 核心 · 明细 · 最近变动 · 签到 · 页脚;没有内容的段不画,同一份列表只画一次。
  3. 一套交互:点开只往下长,行头一个像素不变;长列表默认 3 条 + 原地「全部 N 条」;展开后自动滚进视野;Esc 先收起展开行。
  4. 高度预算:标准字号下,默认展开的整行 ≤ 300px,同屏至少还能完整看到 2 个别的渠道。
  5. 顺手修:「最近变动」的时间全错(秒当毫秒,12 条全挤在 01:57–01:58 这两分钟里);折叠的失败行把「取数失败」说三遍。

4. 新方案

4.1 交互:一种手势,一个结果

  • 点行头 / Enter / Space:展开;再点收起。仍是单开(开一行自动收别的)。
  • 行头前后一个像素不变:原来藏在行头里的「第三段」挪进展开区,展开只往下长,用现有的 320 / 200ms 那一个动画。
  • 先画后取:点开立刻用手头数据画全;「最近变动」先占一行「读取中…」,取到后原地替换,取不到写「读不到变动记录」,不留空白。
  • 滚进视野:展开动画结束后,让卡片下沿进入可视区;卡片比列表还高时,让行头贴住列表顶部。
  • 长列表默认 3 条:最近变动、逐笔到期超过 3 条时,段标题右边出「全部 N 条」,原地展开、变成「收起」。收起整行时复位;轮询重画时保留(与 rowOpen 同一个机制)。
  • Esc 逐层退:有展开行先收起它;没有才走原来的「面板 → 胶囊」。↑ ↓ 在行头之间移焦点照旧,行头加进统一焦点环。
  • 从「最先到期」跳过来:照旧滚动 + 闪一下 + 展开,落点正好是核心段的到期列表。

4.2 骨架:五段,固定顺序,没内容的段不画

段画什么规则
① 核心按口径三选一:金额 = 今日 / 本周 / 本月;配额 = 每个窗口一行;积分 = 最近到期的几笔展开后第一眼看到的东西;原来行头里的第三段就是它
② 明细两列 KV;键 + 值的显示宽度(中日韩字符按 2 计)超过 26 就独占一行,窄的排前面只去确实重复的:本轮额度、可再申请、Codex 的套餐档位、有逐笔列表时的额度包笔数。不按条数截断(落地复核:截断会吞掉「统计范围」「未折进消耗」这类警示)
③ 最近变动只有金额型;默认 3 条 +「全部 N 条」今天的写 HH:MM(聚合的写 HH:MM–HH:MM,跨零点也只写钟点),更早的只写结束时刻 MM-DD HH:MM;去掉外框,和别的段一样用小标题
④ 签到只有开了签到的渠道;一行:连续天数 · 本月合计 · 上次尝试"今天签没签 / 能不能领"是行头徽标的事,这里只说徽标没说的
⑤ 页脚上:一行小字说明(凭据来源 / 统计缺口 / 未公开接口),没有就不画;下:模型配置 · 渠道设置替代原来那层 <details>「数据说明」;缺口写黄。新鲜是默认状态,不写「刚刚更新」
一条硬规则:同一份列表只画一次。折叠行负责"结论"(最紧的那个窗、最近的那笔、还剩几天), 展开区负责"完整列表与动作"。折叠行可以引用列表里的某一项,但不能把列表再画一遍,也不能把同一句提示在两处各写一遍。

段与段之间只靠 8px 间距和小标题分隔,不再有实线框(台账)和虚线框(签到),五段的视觉重量一致。

4.4 高度预算

标准字号下,默认展开(没点「全部 N 条」)的整行 ≤ 300px。列表可视高 413 − 300 = 113,正好再放下两条 51px 的普通行。 大字号 / 特大字号下窗口按同一个倍率放大(formSize,app.js:2211-2217),验收放宽为「同屏至少还有 1 个别的渠道」。 用户点了「全部 N 条」不受预算约束 —— 那是他主动要看的。

预算主要靠两刀:最近变动 12 条 → 3 条(350 → 约 86px);行头不再在展开时长高(第三段 36–83px 挪进核心段,和原来的详情合并成一份)。

4.5 视觉

  • 整行一张卡:展开后行头和展开区同一个底色(--bg2),左侧一条 2px 强调色竖线。竖线用品牌蓝不用状态色 —— 红黄绿已经被状态点和大数字占了;卡比一屏高时,滚到中间也认得出是哪张开着。
  • 一条左边缘:所有段与图标左缘对齐(12px),不再缩进到名称列(49px)。明细两列各从约 150px 放宽到约 175px,长值不再被省略。
  • 字号不加新档:段标题 10.5px --tx3(与分组标题同级);正文 11.5px;页脚说明 10.5px。
  • 「全部 N 条」是文字按钮(--tx2,悬停变强调色),不做描边按钮,不和页脚的「渠道设置」抢眼。
  • 动效不新增:沿用 .rbody 的 grid-template-rows 0fr → 1fr。行头不再变高之后,整次展开只剩这一个动画。

6. 同一块区域里的三个 bug(一并修)

6.1 「最近变动」的时间全错

fmtClock(ts)(app.js:97-100)按毫秒解释入参(new Date(ts)),而三处调用传的都是秒: 台账的 startTs / endTs(app.js:887-888,来自 store.rs:49-58 的 ChangeEntry)和 gapDayFrom(app.js:820)。 后端时间戳统一是 now_ts() = Local::now().timestamp()(fetch.rs:594-596)。

实测同一个当前时刻:当秒传进去得 01:58,换成毫秒得 14:24。7 天的跨度被压成约 10 分钟(604800 秒当毫秒 ≈ 605 秒), 所以 §1 截图里 12 条全挤在 01:57–01:58;「今日从 HH:MM 开始统计」同样是错的。 修法:fmtClock 改吃秒,与 fmtDay(app.js:224-228)同口径。

6.2 OpenCode Go 可能被写成「ChatGPT 订阅」

副标题只要在 extra 里找到「套餐」就写「ChatGPT 订阅 · 套餐值」(app.js:493-496,本意只给 Codex); 而 OpenCode Go 在汇率还没取到时,后端正好往 extra 塞一条「套餐:$10/期 · 未折进消耗(汇率还没取到)」(fetch.rs:357-361), 副标题就成了「ChatGPT 订阅 · $10/期 · 未折进消耗…」。读代码确认,未在真机复现(要等汇率恰好取不到)。修法:这条副标题只认 Codex。

6.3 「未公开接口」没有画出来

README 写 OpenCode Go「渠道定义里标了 unstable,界面上可与稳定渠道区分」,app.js:480-481 的注释也说「未公开接口……明细里都有」—— 但 app.js 里没有任何一处读 unstable。新方案把这句放进 OpenCode Go 展开区的页脚说明(§4.3)。
