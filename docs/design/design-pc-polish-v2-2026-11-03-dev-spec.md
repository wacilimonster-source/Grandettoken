## 5. 布局与尺寸

### 5.1 窗口与滚动

- 正式窗口结构：标题栏 → 可滚动主体 → 固定页脚。主体包含概览标题、三格摘要、筛选、渠道列表。
- 编写时源码内容区最小 `340×460`、默认 `380×560`、最大 `740×920`，外层各有 10px 透明边距。因此标准字号实际窗口最小 `360×480`、默认 `400×580`、最大 `760×940`。以 `panelBounds()` / `panelDefaultSize()` 为准，不把内容尺寸与窗口尺寸混用。
- 沿用 `winW` / `winH` 存内容区逻辑像素、`winX` / `winY` 存现有位置口径的规则，尺寸倍率仍由现有机制处理。
- 双列断点采用现有有效宽度规则：`内容区宽 / 字号倍率 >= 720` 为双列，低于此值为单列。原型 500px container query 仅为演示简化，正式不要照抄。
- 单列卡片：左图标与名称，右主数字与限定语，下方状态轨。双列卡片：顶行品牌、第二行主数字、底部状态轨。
- 页脚、标题栏始终可见；只允许主体纵向滚动，不产生水平滚动。长渠道名省略，完整名称保留可访问文本；关键状态与到期时间不能只剩省略号。
- 大字号时可以减少同时可见卡片，不得以降低正文字号换取密度。
- 不自动放大窗口迁就卡片数；拖动缩放后保留用户选择。进入胶囊后再展开恢复面板原尺寸与位置。
- 保留原生可拖拽标题区；所有按钮、输入和弹层可操作区不得被拖拽区覆盖。

### 5.2 推荐视觉尺寸

以下是标准字号下的逻辑 px，随 `--u` 缩放，固定透明边距除外。

| 元素 | 基准 |
|---|---|
| 外壳圆角 / 卡片圆角 / 输入圆角 | 16 / 10 / 7 |
| 标题栏 / 页脚 | 55 / 43 高；若字号需要，允许增高 |
| 主体内边距（宽 / 窄） | 20 / 14 |
| 卡片间距（宽 / 窄） | 10 / 8 |
| 卡片内边距 | 14（窄屏 12–13） |
| 渠道图标 / 标题品牌图标 | 30 / 23 |
| 首页标题 / 卡片数值 / 详情数值 | 20 / 27（窄 25）/ 42 |
| 渠道名 / 正文与辅助说明 | 12–13 / 最低 11.5 |
| 到期摘要日期 / 时间 | 23 / 13 |
| 图标按钮可点区域 | 常规 28，最小 24；键盘焦点清晰 |

原型残留的 9–11px 小字不作为正式字号要求；中文可读正文统一最低 11.5px，特别是来源、倒计时、错误提示和页脚状态。金额小数使用等宽数字，人民币符号和积分单位采用小号，不能与主数字同大。

## 6. 颜色、组件与动效

| 语义变量 | 深石墨 | 暖雾白 |
|---|---|---|
| bg | `#15181b` | `#f6f7f3` |
| surface | `#1d2125` | `#ffffff` |
| raised | `#262b30` | `#eef1e9` |
| border | `#30363b` | `#dce0d6` |
| hair | `#2a3035` | `#e6e9e0` |
| text | `#f0f2ed` | `#272e28` |
| secondary | `#afb8bb` | `#606d62` |
| quiet | `#849095` | `#717b70` |
| accent / lime | `#d3e6a3` | `#4c632f` |
| ok | `#8bc9a2` | `#427650` |
| warn | `#edc185` | `#946120` |
| bad | `#ef9d94` | `#b7483c` |

- 原型变量映射到现有 `--bg*`、`--tx*`、`--ok`、`--warn`、`--bad`、`--ac`，选一套语义变量统一使用，不维护两套互相覆盖的 token。
- 鼠尾草绿用作选中与主按钮；黄和红只表达风险、陈旧或失败。正常金额进度条不染成预警黄。
- 卡片悬停提亮表面和描边，不做大幅缩放；数字不跳动、不滚轮动画。
- 图标统一 currentColor SVG，品牌用现有本地资产。暖白主题中白色 Codex 标做合适的深色适配。
- 焦点用 2px 描边，不能仅靠 hover。状态必须同时有文字或形状，不只靠颜色；保留 `textTone` 偏好。
- 交互 120–200ms，弹层进入约 220ms，宽度示意约 250ms；正式原生拖拽尺寸不加滞后 transition。尊重 `prefers-reduced-motion`。
- 表中文字对比度按普通文本 4.5:1 检查；token 是设计起点，对实测不达标的组合提亮文字或调整表面。

## 7. 首页行为与三类数字

### 7.1 摘要与筛选

| 元素 | 动态数据与动作 |
|---|---|
| 临期积分 | 本设计目标为未来 7×24h 内、可见积分渠道中已确认未到期记录的剩余积分合计；不是总余额 |
| 最先到期 | 上述集合中最早 `at`，展示日期/倒计时、渠道和该笔数量；点击打开对应渠道，不固定为 Trae |
| 每日签到 | 已启用且可见渠道中的今日已完成数 / 应完成数；点击签到中心 |
| 全部渠道 | 可见渠道数，遵守用户隐藏与已有自动隐藏策略 |
| 需关注 | 使用统一视图中需要关注的渠道状态/色调，加上可确认的临期提醒；不把所有 points 渠道都视为告警 |
| 余额 | 只显示 `kind === 'amount'`；配额和积分不混入 |
| 搜索 | 渠道显示名匹配，与当前筛选取交集；收起搜索清空关键词；空结果给明确提示 |

摘要 7 日范围是此版目标，与旧 `expirySummary()` 的 30 日逻辑有差异；实现时显式抽出 `SUMMARY_EXPIRY_DAYS=7` 并同步文案。详情仍列所有记录，已有风控、通知和 30 日历史查询不跟着改窗口。

若部分积分渠道的 `expiryComplete !== true` 且仍有余额，显示「已知临期」或加注「部分渠道到期信息未知」。已知合计为 0 且有未知数据，显示「已知 0 · 部分未知」，不能宣称「全部无到期」。没有可用记录时最先到期显示「暂无已知到期记录」，禁用跳转。

### 7.2 渠道卡片

- `amount`：展示剩余金额及实际币种。仅在已知分母时画比例条；4SAPI 分母为 `claim.amount`，不能用累计发放 `total`。DeepSeek / Hapi 充值型没有分母时不画进度条。
- `percent`：显示剩余百分比与窗口限定语，不与金额、积分求和；不画原型以外的新进度条。Codex 周窗主数字、5 小时副数字、重置卡都保留，倒计时宽度不够时复用 `fitCodexResetLabels()`。
- `points`：主数字为可用积分；状态轨优先显示失败/旧快照，其次临期提醒，其次签到或到账状态。WorkBuddy 的逐笔到期通过卡片点击即可到达，无须先触发告警。
- 卡片主数字、色调、紧迫度和排序优先消费 `HomeView.rows` / `FormRow`，统一四形态结论。不能照抄原型 `state==='warn'` 来重建状态机。
- `null` / 无字段显示「—」或「数据不足」，确定的 0 显示 0；取数失败不改成余额 0。
- 沿用用户排序和隐藏选择；原型把 Trae 固定排第一仅用于演示。

## 8. 渠道详情弹层

### 8.1 容器与生命周期

1. 点击任意可见渠道卡打开对应 ID 的单例 dialog；管理页相关预览入口如存在，也必须打开同一数据。
2. 自标题栏下缘至页脚上缘放遮罩，底部弹层上缘圆角 16px，宽度填满内容区。背景轻微模糊，遮罩不影响真实窗口透明角。
3. 弹层头部固定可见：图标、名称、账户说明、关闭按钮。主体单独纵向滚动；动作区可固定底部。最小窗口和特大字号下，关闭入口不能滚出可视区。
4. 主体：余额/配额数字 → 核心说明 → **积分到期信息** → 其他业务详情 → 数据来源/快照说明。积分到期默认可见，不藏到二级页签或统计图下面。
5. 关闭方式：关闭按钮、点遮罩空白、Esc。Esc 先关闭最高层弹窗，不能同一次按键继续把窗口收成胶囊；无弹窗时恢复原有快捷键行为。
6. 打开后焦点进入弹层；Tab / Shift+Tab 限定在弹层，背景主体不可键盘操作。关闭后回到触发卡片；卡片因筛选消失则聚焦列表标题。
7. 刷新推送仅更新当前 ID 的内容，保持弹层开启、滚动位置、展开状态和合理焦点。渠道被隐藏或移除则关闭并提示；切换胶囊前关闭详情。
8. 「设置与管理」关闭弹层并定位到该渠道配置卡，不能总跳到管理页顶端；返回时恢复渠道列表位置。
9. 「刷新数据 / 重试连接」复用现有真实刷新链路，处理中禁用重复点击，成功后展示新快照，失败保留旧数据和真实原因。不要编造单渠道刷新 IPC。
10. 现有展开详情中的 7 日消耗、明细、最近变动、签到、重置卡、峰谷、账户切换和缺口说明都要迁移或保留可达入口。替换容器不等于删减业务。避免同一份详情同时保留内联和弹层两套渲染状态。

### 8.2 积分详情的固定结构

| 顺序 | WorkBuddy / Trae | Qoder / Qoder 国内版 |
|---|---|---|
| 1 | 总可用积分与单位 | 总可用积分与单位 |
| 2 | 最近一笔到期：完整日期、时间、倒计时、该笔剩余积分 | 账户额度到期：完整日期/可用精度、长期有效或未知 |
| 3 | 逐笔列表：到期时间、来源、剩余积分、相对时间 | 逐笔积分到期：有数据则列表，没有则明确未知 |
| 4 | 完整性、旧快照、时区说明 | 账户有效期不代表逐笔有效期的说明 |
| 5 | 其他已有详情和真实操作 | 其他已有详情和真实操作 |

**WorkBuddy、Trae 都使用同一个积分详情组件。不能再做 `id === 'trae'` 才渲染到期列表的分支。** WorkBuddy AI 作为独立渠道复用组件；其签到、活跃奖励口径继续按真实渠道能力处理，不能误加国内版签到功能。

## 9. 到期数据契约与边界

### 9.1 复用的真实字段

前后端 serde camelCase；以下是线上视图形状说明，不是新增接口：

```ts
type Expiring = {
  at: number;       // Unix 秒，不能直接当 Date 毫秒
  amount: number;   // 这一笔尚未使用的积分，不是原始发放量
  label: string;   // 来源，如「活动赠送」；不解析名称来猜日期
};
type PointsViewSubset = {
  id: string;
  kind: 'points';
  remaining: number | null;
  expiring: Expiring[];
  expiryComplete: boolean;
  expiringSoon?: Expiring | null; // 现有约 30 日聚合，不直接替代“最近一笔”
  extra: [string, string][];
  valid: boolean;
  stale: boolean;
  updatedAt: number; // Unix 秒
};
```

- Trae：继续复用 `extract_trae` 中逐包 `expire_time`、剩余量和完整性处理，不在 JS 重新解析原始接口。
- WorkBuddy：继续复用 `extract_workbuddy` / `wb_expiry_at` 的归一化；到期优先级是 `DeductionEndTime` → `ExpiredTime` → `CycleEndTime`。毫秒/秒、北京时间字符串由后端处理，不能由前端试错猜。
- WorkBuddy 的退款、过期状态和切片额度计算沿用当前后端，前端不再次推算有效余额。`Expiring.amount` 为剩余量。
- 时间值必须有限且有效；无法解释的值归未知，不显示 `Invalid Date` / 1970-01-01。
- 以服务端归一化结果为准，不能从「每日签到」「活跃奖励」文案推定积分有效期。

### 9.2 排序、完整性与过期

```text
now = 当前真实时间（测试可注入固定时钟）
known = 有合法 at、有限正数 amount 的返回记录
upcoming = known 中 at > now 的记录，按 at 升序，稳定保留同时间的来源记录
past = known 中 at <= now 的记录，单独作为“已到期 / 待刷新”显示
nearest = upcoming[0]；同一时刻多笔在摘要可合计，明细仍分列
summary7d = upcoming 中 at <= now + 7*86400 的可见记录
```

- 后端已经过滤的记录不在前端补回；若已有旧快照包含到期记录，单独说明「已到期，待刷新」，不能继续作为未来临期。
- 默认展示最近 3 笔，更多时显示「全部 N 笔」，原地展开/收起；已过期记录放在单独分组或展开后的末尾，不能占掉最近 3 笔。
- 仅有 `past` 时显示「没有未到期的已知积分包」，并保留已到期分组，不展示负数倒计时。
- `expiryComplete=false` 且有记录：仍显示已知记录和「到期信息不完整」，最近卡写「最近已知到期」，不宣称是所有积分的最近一笔。
- `expiryComplete=false` 且无记录：显示「逐笔到期时间暂未提供」，不是「无到期」或「长期有效」。
- `expiryComplete=true` 且无记录、remaining>0：显示「当前剩余积分没有已知到期日」，不能仅由空数组断言永久有效。
- 确认无剩余积分：总额显示 0，说明「当前没有剩余积分」；如果还有残留到期记录，标记数据不一致并请求刷新，不据此增加余额。
- `expiring` 总和少于余额不自动补造“其他积分包”；多于余额也不改写总额。标记口径差异，继续使用后端余额。
- 到期日期与相对时间随本地 ticker 更新，不需要为了倒计时额外发网络请求；到点标「已到期，待刷新」，沿用轮询刷新。

### 9.3 Qoder：账户有效期单独处理

编写本文时，Qoder `expiresAt` 被后端转为 `extra` 中的「账户额度到期」，有限日期只保留 `YYYY-MM-DD`；极远日期哨兵转为「不过期」。逐笔列表当前未提供，`expiryComplete=false`。

正式实现需要同时支持：

| 数据 | 显示 | 不可做 |
|---|---|---|
| 明确有限账户到期时刻 | 「账户额度到期」+ 日期与可靠的时间；计算账户倒计时 | 不能声称全部积分同刻过期 |
| 明确不过期哨兵 | 「长期有效」+「账户额度不过期」 | 不能声称逐笔积分永久有效 |
| 无有效字段 | 「账户额度到期暂未提供」 | 不能用未知代替长期有效 |
| 只有旧 `extra` 的日期字符串 | 只展示这一天，不画 `23:59` 和小时倒计时 | 不能把日期-only 解释成午夜或当天末尾 |
| 将来确实拿到逐笔信息 | 另外显示逐笔表 | 不能让账户卡替代逐笔信息 |

为实现原型中的分钟级展示，建议在本轮以**兼容性增量字段**扩充 provider / ChannelView，而不是在 JS 解析中文 extra：

```ts
// 建议新增到 ChannelView / FetchResult 的可选字段；是实施目标，不是现有字段。
accountExpiry?: {
  state: 'dated' | 'never' | 'unknown';
  at: number | null; // dated 时为归一化 Unix 秒，其他状态 null
};
```

Qoder 直接从原始 `expiresAt` 生成结构化字段；现有 `extra` 继续保留以兼容旧视图。后端 `ts_norm()` 和现有哨兵阈值复用，不在前端硬编码年份 9999。缺字段旧快照通过 `extra` 文本只读回退，严格日期-only 呈现；回退必须限定 Qoder，不把其他 arbitrary extra 解释成日期。

增量字段要覆盖 FetchResult / ChannelView 所有构造、快照失败回退、serde 默认、缓存兼容；检查 Android / 同步等序列化消费者，只增加可忽略字段，不顺带升级同步协议。无须为此次视觉修改重写数据层。

### 9.4 时间展示与提醒色

- 积分到期展示绝对日期 `YYYY-MM-DD HH:mm` 与相对时间；所有视图使用同一时区格式化函数。正式应用用系统本地时区并标识 UTC 偏移；原型固定 UTC+8 只是演示。
- 不加 `Z` 去解释北京时间字符串；跨时区转换在归一化时间戳后进行。
- 相对时间是当前时刻到到期时刻的差值，不复制原型里的「9 天后」；少于一小时显示分钟、少于一天显示小时/分钟，精度取整需全应用一致。
- 若显示「明天 / 今天」，按展示时区的自然日判断，不能用“剩余不足24小时”替代“今天”。
- 最近卡对未来 7 日内的已知积分到期可作柔和黄提示，正常远期保持中性；过期旧快照有文字标识。全局警报颜色和系统通知仍按现有 HomeView / 配置规则，不因展示色升级而新增通知。

## 10. 设置与持久化

- 索引顺序以 V2 为参考：渠道、模型、签到、显示、刷新与启动、密钥箱、同步、关于。渠道能力决定是否显示签到入口，关闭所有签到后不保留固定 3/3。
- 现有管理页面字段和验证保持可达：显隐、排序、密钥/登录来源、阈值、申请规则、自定义渠道测试、模型配置预告/备份/回滚、同步恢复等。
- 主题新增 `theme: 'dark' | 'light'`，默认 dark，配置校验非法值回 dark，老配置缺字段可正常读取。Rust / JS 配置兜底与设置控件一起更新。
- 主题切换即时预览、调用真实 `set_config` 持久化，重启保持；保存失败明确提示并恢复最近已保存主题，不能 toast 成功但未落盘。
- 使用当前配置对象增量合并保存，不用原型对象整体替换 CFG。尤其不能丢失用户渠道密钥引用、同步、排序和更新设置。
- 字号继续 `md=1 / lg=1.15 / xl=1.3`；原型 1.12 不是落地值。开关 role=switch、aria-checked 与真实配置一致，保存失败恢复 UI。
- 置顶必须走现有 `set_pin`，只有成功后才显示已置顶。隐藏走 `window_cmd(action='hide')`，退出复用 `quit` 等待写入完成的现有流程。
- 保留胶囊、可选紧凑条、贴边竖条、全局快捷键、托盘、更新提示和自动刷新。紧凑条默认关闭，标题栏始终四入口。
- 退出只保留页脚和托盘；新浅色主题也覆盖胶囊、紧凑条、贴边态及更新/设置弹层。

## 11. 运行状态、可靠性与性能

| 场景 | 预期呈现 |
|---|---|
| 初次加载无快照 | 骨架/加载文字；不显示伪造数字 |
| 首次失败无历史 | 「取数失败」+ 原因 + 重试；主数字 — |
| 失败但有成功快照 | 上次成功数值与到期信息保留、明确「上次快照 / 更新于…」；不过度承诺当前有效 |
| 无凭据 | 未配置/需登录 + 正确管理入口，不显示 0、不计普通告警 |
| 限流 | 窗口与真实重置时间，Codex 双窗保留 |
| 搜索无结果 | 空状态和可清除搜索，不渲染空白窗口 |
| 渠道全部隐藏 | 空状态 + 渠道管理入口，不擅自恢复被隐藏渠道 |
| 签到未启用/失败/待确认 | 用现有状态，不能统一绿色完成 |
| 配置保存失败 | 可见错误、UI 与真实状态一致，不写假成功 |

- 金额消耗使用 `day/week/month`，`estimated` 明确「推算」，`gap*` 和 `accounts` 说明不丢失。原型金额详情里的固定 ¥2.40 等全部删除。
- 跨形态数字、状态同源；不要为胶囊单独缓存一份能永远显示绿色的状态。
- 渠道推送事件不能重绑多份监听器；倒计时更新定向节点，不每秒重建整页。不要每帧 IPC 查询几何或保存配置。
- 对渠道名称、错误、来源、extra 等动态文本继续使用现有 `esc()` 或 textContent；不把原型直接拼接示例当安全模板。
- CSS 阴影不得越过真实透明边距产生截断硬边；现有阻止 body 背景传播的 html 背景规则保留。

## 12. 推荐实施顺序与完成边界

每个阶段都保持应用可用；顺序不是要求拆成多个 PR。

1. **现状与基线**：检查 `git status`、当前约束与脚本依赖；记录现有截图、默认尺寸、配置读取、WorkBuddy / Trae / Qoder 实际字段。保留用户/其他 agent 未提交变更。
2. **视觉基础**：主题变量、字体阶梯、外壳与表面；增加向后兼容主题配置；不先复制原型整页覆盖正式文件。
3. **首页**：真实卡片、三格摘要、筛选、宽窄布局与状态轨；统一 HomeView 数据来源。
4. **详情与到期**：单例弹层、公共积分组件、WorkBuddy 与 Trae 逐笔到期、Qoder 结构化账户有效期/旧快照回退。这个阶段是用户点名的重点，不能作为可选后续。
5. **设置与形态统一**：索引和子页样式、真实保存与错误恢复、胶囊/紧凑/贴边、退出、更新等现有入口。
6. **验证与交付**：下表用例、相关脚本、截图对照、更新产品说明和变更报告。

最终需交付可运行代码、相关验证结果、PC 截图与真实遗留限制。只改静态原型或只截图不算完成后续开发任务。编译、真机或依赖受环境限制时如实报告，不能声称全量通过。
