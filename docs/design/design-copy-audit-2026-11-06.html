§1全局文案规范（文案宪法 v1）

以下 7 条规则是后面所有逐条改法的依据；先定规则，逐条表只列「不符合规则」的项。

1.1 标点基线：句中半角，句末全角P0

现状 90% 文案已经遵守一种隐性风格——句中停顿用半角 , : ; ( )（紧凑、省宽），句子收尾用全角 。？ 或不加标点。把它定为明文规则：

  • 句中一律半角：, : ; ( ) /。收编现有全角点：同步模块全部（约 45 条）、download.rs（6 条）、确认框正文（6 条）、index.html:307、4089 排序：4254（已隐藏）、7655/7656/7967/7992-7993、4387/4638/4802/6136 等。
  • 句尾：问句用全角 ？；陈述句尾不加标点；多句正文（confirm 正文、折叠段）可用全角 。 分句。6208 的半角 ? 收编为 ？。
  • 引号一律「」直角引号（现状已遵守）；省略号一律单字符 …；破折号一律双横 ——（插值注释）；数值占位 ——；数学负号保留 −（U+2212，台账专用）。
  • 明确不做「全面全角化」：改动 200+ 条、与紧凑风格冲突，收益低。

1.3 错误文案：三段式 + 外部原文不出用户面P1

  • 模板：<对象><动作>失败: <中文短原因>。短原因 ≤ 20 字、说清「什么事没成」，需要时再接 · <一句话出路>。errcodes.rs 的 19 条短文案是全应用范本。
  • 外部库原文（reqwest / serde / rusqlite / updater / Windows API 的英文 e）不再拼进用户可见首句：替换为固定中文短语，完整 {e} 写入诊断日志（diaglog 已有事件管线，加一行即可）。逐条改法见 §3.2。
  • 错误码对用户隐藏：SYNC_XXX: 中文 组合到达界面时只显示中文消息；码本身保留在「设置 → 诊断」（Android 已有该展示位）、体检报告与日志里，报障链路不丢。
  • 第三方平台原文（平台返回的 message）保持透传但包一层：平台返回: {msg}，与自家文案区分。

1.4 toast 守则P1

  • 成功回执 ≤ 14 字，动词开头：已复制 / 已保存 / 已删除 / 已发布 / 已加入同步组。
  • 剪贴板回执只有两种：普通 = 已复制；密钥 = 已复制 · 剪贴板对其他程序可见（安全提醒只保留密钥这一处）。诊断/日志类 = 已复制 · 可直接粘贴给 AI 排查（替换「贴给我」两种变体）。
  • 失败 toast 必须含出路或可诊断信息（现状大部分已做到）；纯「已 X」的冗余回执（界面同屏已有反馈）进减法清单，见 §5.1。
  • 机制不动：单条覆盖、2600ms、role="status"。

1.5 空态三档 + 每个空态必须给出路P2

三个空态（未配置 / 全隐藏 / 筛选无结果）现状已带 CTA 按钮，是范本。规则化：凡空态必含「下一步」——按钮或一句话指路。目前仅两处缺口：签到中心全关页（7210 已有指路，合格）、活动筛选空态（7121「当前筛选下没有活动」无出路 → 加「换个筛选或点『全部』」）。

1.6 数字、单位与时间P2

  • 金额 ¥12.34、积分 1,234 分、百分比整数位优先（列表）+ 1 位小数（详情），现状已统一，不动。
  • 相对时间 刚刚 / N 分钟前 / N 小时前 / N 天前 / 从未 三端已一致（Android 同款实现），写入规范。
  • 「连续失败后」等设置项描述 每 24 小时最多问一次服务器 这类口语化说明保留——这是产品的语气资产。
