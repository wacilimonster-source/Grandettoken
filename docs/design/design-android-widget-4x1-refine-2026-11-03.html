ONE OBJECT

外框就是对象

名称、数值、窗口标签都在同一个外框内；不再有“底部颜色 + 内部文字”的上下层错觉。外框本身承担图标级的识别。

SAME MATERIAL

和图标同一种材料

圆角、细边、半透明和阴影都向桌面图标靠：外框看起来是一个桌面对象，而不是一张深色横幅。

READABLE

内容只做内缩

深色玻璃保证文字对比；内边距让内容离开边框，但不加第二层背景、不给数字加大阴影。第一眼先看到完整外框，再读到数值。

01 / WHY

为什么这样改

不是把卡片做大，而是把信息层级做对

LARGER · VALUE FIRST

数字先被看见

当前 4×1 的值是 12sp，窗外标签和“周剩 65.0%”挤在同一行。新稿把名称/窗口降到 10sp/8sp，值提升到 16sp 并保留小数和单位，首眼先读到 65%、82%、¥76.50。

WINDOW · STABLE KEY

窗口标签取代长句

用「周」「5h」「月」小标签说明数值对应哪个窗口；值只显示百分比。这样同一行能容纳更大的字，也避免“周剩 65.0%”这类长文本被截断。

DUPLICATE · SAME CHANNEL

同渠道可以占两格

Codex 的周额度和 5 小时是两个独立窗口。选择模型从“渠道”升级为“渠道 + 窗口”，所以它们可以同时出现；重复的是条目，不是同一窗口。

03 / CONFIG

选择条目，而不是选择渠道

Codex 两个窗口可以同时被选；每个条目独立排序

SELECTED · ORDERED

已选列表

先显示已选条目，按桌面从左到右/从上到下排列。箭头只移动当前条目，所以可以把“Codex 周”放在“Codex 5h”前面，也可以把两个 Codex 分开。

AVAILABLE · GROUPED

按渠道分组

Codex 下出现“周额度 65%”和“5 小时 78%”两个可选项；OpenCode Go 只提供“月额度 82%（按套餐周期）”。同一窗口不会重复添加。

LIMIT · 3 / 4

条目上限

4×1 最多 3 个条目，4×2 最多 4 个。选满后未选项置灰；想再选 Codex 5h，需要先移除一个其他条目。选择不会影响 App 首页排序。

示意：配置页的“月额度”对应接口的周期窗口，按套餐开通日滚动，不是自然月；标签仍写“月”，详情页可注明“按套餐周期”。

04 / CONTRACT

需要补一个稳定的窗口键

不要用中文标签做选择语义

// Android 收到的窗口快照需要能稳定选中
WindowSnapshot {
  key: "weekly" | "5h" | "monthly" | "rolling",
  label: "本周" | "5 小时" | "周期", // 仅显示
  remainPercent: "65",
  main: true // Codex=周, OpenCode=月
}

WidgetSelection {
  platformId: "codex",
  windowKey: "weekly" // 或 "5h"
}
WHY KEY

标签会变，键不能变

Codex 的窗口标签由窗口秒数生成，OpenCode 的月窗口当前叫“周期”。如果按中文标签选窗口，某天文案调整就会静默失效；稳定键和 main 标记才能保证“Codex 默认周、OpenCode 默认月”。

兼容旧版电脑端旧快照没有 key/main 时，小部件退回旧的“整渠道”选择，只显示一个主窗口；新版电脑端发布后，配置页才出现周/5 小时/月的多条目选择。旧 Android 收到新字段会忽略，不需要同步码或协议版本升级。
05 / STATES

状态与验收边界

旧数据仍然保留，但不假装成新数据

场景4×1 展示行为
正常大数值 + 周/5h/月标签；右侧“最早 14:07”值完整保留小数；标签说明窗口。
某条目较旧该条目名称旁出现“!”、标签变暖色；右侧“较旧 12:14”保留最后可信值；不把旧值写成“刚刚”。
同步失败 / 离线右侧“失败/离线”；值仍保留不把失败当 0；刷新失败不丢数据。
窗口不可用该条目显示“—”，标签灰色；右侧“不完整”保留选择，切回有数据的电脑或重新同步后恢复。
未加入 / 无缓存空状态“先加入同步组 / 等待首次同步”不显示示例或虚构数值。
Codex 双窗口同一行出现两个 Codex：周 65% 与 5h 78%两个条目独立排序、独立显示较旧/不可用；点任一进入同一详情页并定位对应窗口。
4×2两列网格，最多 4 个条目同样支持 Codex 双窗口；空间更宽，值可略大。

真机还需验证：HyperOS 3 的 4×1 实际占格、16sp 在 200% 系统字体下是否可读、长渠道名/大字体下是否自动减少可见条目并提示“+N”。这些不影响本设计的交互模型。
