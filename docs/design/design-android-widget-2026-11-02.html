01 / CONCEPT

两个尺寸，同一份数据

已讨论确认的范围与建议的首版细节

CONFIRMED · 4×1

横条，快速扫一眼

横向放置渠道名称与核心数值。设计建议最多选择 3 个；空间或系统字体不足时减少可见项，提示还有几项，点击进入 App。

CONFIRMED · 4×2

卡片，看得更从容

以两列网格列出渠道、数值与必要状态。设计建议最多选择 4 个；配额窗口有明确标签，异常渠道可直接标记“较旧”。

CONFIRMED · PERSONAL

手动固定，顺序不乱

每个小部件单独选渠道并排序；App 首页排序变化不影响它。横条从左到右排列，卡片先左后右、再到下一行。容量和比例需在真实桌面与字体大小下验证。

02 / JOURNEY

从添加到查看

1

添加到桌面

桌面双指捏合 → 小部件 → 搜索 / 安卓小部件 → Grandettoken → 选择尺寸。不同系统版本的入口名称可能略有不同。

2

选择渠道并排序

首次添加后进入配置页，勾选渠道，调整前后顺序并保存。两个尺寸各自配置；重复添加时每一份独立保存。

3

看状态，按需刷新

点渠道进入对应详情；点刷新按钮拉取同步组。之后可从 App 设置中的“小部件”管理每一份配置；系统支持时也可从桌面编辑。

03 / CONTENT

显示什么，怎么理解

项目设计规则例子 / 说明
金额型显示原始币种与余额；不同币种不直接相加。4SAPI ¥76.50，DeepSeek ¥256.00。
配额型标明百分比对应的时间窗口；仅有主百分比时按已有字段显示，不猜测窗口。Codex 周剩 65%；有空间且数据存在时再显示 5 小时窗口。
积分型显示积分数与单位；到期明细进入渠道详情查看。Qoder 148 积分。
无值 / 不可用无值显示“—”；已选渠道从同步组消失时显示“渠道不可用”，保留选择供调整。不将缺失、失败或无记录显示为 0；不拿被移除渠道的旧值冒充现值。
时间“最早采集”指当前可见、且有有效值的渠道中最早的电脑端成功采集时间；日期不是当天时显示日期。存在无值时同时提示“数据不完整”。手机刚同步成功也不能把旧的电脑数据写成“刚刚更新”；时间异常显示“时间异常”。
放不下时在不低于可读字号的前提下，优先保证数值、单位、状态；缩短名称，必要时按已选顺序减少可见渠道并提示“+N”，点击进入 App；已保存的选择不变。不靠截掉小数或币种符号伪造完整数值；详情显示完整内容。
04 / STATES

让旧数据一眼可辨

状态变化保留可理解的下一步

状态小部件展示用户可以做什么
未加入同步组“先加入同步组”，不显示示例数值。点卡片打开 App 的加入同步组页面。
已加入，无缓存“等待首次同步”；首次加载时不显示虚构余额。打开 App 或点击刷新；电脑需要先发布数据。
某渠道较旧当上游标记失败 / 陈旧，或采集时间已达 2 小时，在下次小部件更新时标记该渠道较旧，并保留其可信值和时间。点渠道查看详情；通过文字与图标提示，不只依赖颜色。
手机同步失败 / 离线保留上次可信数据，提示“同步失败”或“离线”及最早采集时间；不把失败当成 0。检查网络、点刷新或打开 App 查看原因；限流时给出稍后重试的提示。
渠道移除或退出组渠道移除时显示不可用；清缓存、退出组或切组时立即清除旧组显示，不能残留旧余额。重新选择渠道或加入新组。桌面本身会展示数值，请按自己的隐私需要摆放。
05 / FRESHNESS

刷新的是同步快照

SOURCE

电脑先采集、再发布

电脑向各渠道取数并发布加密快照，手机读取并解密。电脑离线或未发布时，手机刷新不会让电脑重新取数。

BACKGROUND

复用一套后台同步

沿用手机现有的 15 / 30 / 60 分钟后台设置和同一份缓存；系统可能延后执行，不承诺准点或实时。

MANUAL

手动刷新有反馈

点击后显示刷新中 / 成功 / 失败；建议 App 和小部件共用 30 秒手动节流，合并与后台重叠的请求，并遵守服务端限流。数据未变化时仍保留原采集时间。

06 / HYPEROS 3

小米手机的适配路线

4×1 是目标尺寸，仍需在你的 HyperOS 3 真机上验证。本方案建议先使用原生 Android App Widget。Android 文档提供 4×1 尺寸设计参考；小米公布的“小米专属小部件”规范列出的是 2×2、4×2、4×4。两套体系不同，不能据此认定原生 4×1 一定支持或一定不支持。先用最小原型验证原生入口、实际占格、字体和点击；若实际不支持，再讨论替代方案，不自动把 4×1 改成别的尺寸。
01 · FIND

添加入口

原生小部件走系统支持的安卓小部件入口，不依赖小米专属小部件审核；不同桌面版本的入口与展示需实测。

02 · FIT

真实占格

分别测试 4×1、4×2，检查桌面行列设置、大字体、长名称、深浅壁纸和横竖屏下的可读性。

03 · UPDATE

后台可靠性

测试熄屏、省电、网络恢复、重启及系统限制；若刷新长期延迟，先给出有针对性的系统设置引导。

07 / DELIVERY

后续开发的验收重点

配置与交互

  • 两种尺寸均可添加，独立选渠道、排序、保存和重新编辑；删除一份不影响另一份。
  • 按渠道进入对应详情；刷新有明确反馈；字号放大后仍可操作。

数据与异常

  • 上游采集时间、手机同步时间分开；304 不改变采集时间；过旧、离线、缺失、限流均不伪装为正常新数据。
  • 退出或切换同步组后，桌面不残留旧组信息。

耗电与隐私

  • 多个小部件共用同步任务；快速连续点击和与后台任务重叠不会造成请求风暴。
  • 小部件只显示所选内容，不显示同步码、Token 或密钥；真机检查电量与后台限制。

客户端已实现并通过 Android 模拟器交互测试；HyperOS 3 真机的 4×1/4×2 占格、字体缩放和后台刷新仍需验收。本文是产品设计及交互示意；容量、刷新交互和视觉样式以真机结果为准。
