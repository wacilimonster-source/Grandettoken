紧凑条 / 胶囊:贴内容布局 + 信息降级

2026-09-18 设计稿(未改代码)· 目标:内容尽量多展示、窗口贴合内容不留空白、各种数据长度/字号档位都不破相。所有演示为真实尺寸(46px 高),可切场景与档位。

一、现状两个问题(虚线 = 现在的固定 380px 宽)

现状:窗口永远 380 宽,两个渠道时右半全空;chip 只有图标+数字,能放下的名字被藏掉了

二、方案:宽度贴合 + chip 三级信息降级

新:窗口贴内容(上限 380×字号倍数);空间够就把「名字」放回来,不够逐级降,超载才收 +N

三、降级规则(兼容各类情况的核心)

级别chip 内容触发条件例子
L0图标 + 名 + 数贴内容宽度 ≤ 380×u 时装得下全部[4S] 4SAPI ¥74.20
L1图标 + 数(现状)L0 超宽 → 从最宽的 chip 起逐个去名字[4S] ¥74.20
L2图标 + 缩写数L1 仍超(长数字+特大字号)→ 小数舍掉(74.20→74,6,075.5→6.1k,82.0%→82%)[WB] 6.1k
+N收纳尾部全降到 L2 还超 → 尾部渠道进徽标(现有机制)… +2
  • 降级顺序先"去名字"后"舍小数"再"收 +N":名字是"谁"、小数是"精确到多少"——挂件场景里"谁"更重要、精确值点开面板就有;
  • 窗口宽 = 内容宽:和胶囊同一套路(量完再 setSize,走既有几何队列,不会触发折叠竞态);上限 380×u 保底,不再出现半排空白;
  • 0 渠道/全隐藏:紧凑条收成「未配置 + ⚙」最小 chip,不再空荡 380;
  • 胶囊:只改下限钳位 132→104 ——「505」「8%」这类短数现在被撑到 132 宽、两头留白;上限实测维持 240 即可(要 15 位级数字才碰得到,本产品不会);其余逻辑不动;
  • 兼容矩阵:6 类渠道(金额/积分/%/失败/未配置/隐藏)× 3 字号 × 100%/150% DPI × 吸附展开态 × 拖到屏幕边缘(clampToMonitor)——宽度都是"量出来的",天然适配;
  • 轮播/刷新时机:数字变化导致宽度变化 ≥6px 才重钳窗口(沿用胶囊防抖阈值),不会抖。
