紧凑条改为可选开关 · 产品设计

2026-10-23 · 依据 v0.1.63(a2213b5)代码实读 · 本文只做设计,未改动任何代码

0. 结论

  1. 一个开关:设置 → 显示 → 外观 →「启用紧凑条」,默认关。
  2. 关闭时:顶栏不显示「紧凑」按钮;Ctrl+2 不生效;Esc 只在面板 ↔ 胶囊之间走;任何来源的 compact 形态都落脚到面板。
  3. 一个收口:所有切换入口都经过 applyFormInner,在那里判一次就够了 —— 以后再加入口也不会漏。
  4. 代码不删:紧凑条的布局、宽度重排、条尾按钮、快捷键分支全部保留,打开开关后与今天完全一致。

用户真正能碰到的只有前三个(按钮 / Esc / Ctrl+2);后三个都是"跟着当前形态走"的派生路径。 所以只需要:① 藏按钮;② 改 Esc 的落点;③ 关掉 Ctrl+2;④ 在 applyFormInner 兜底。

2. 规则

2.1 配置

新增 compactEnabled: bool(Rust compact_enabled),默认 false。 只加字段、不写迁移脚本:配置层已经是 #[serde(rename_all = "camelCase", default)](config.rs:44-46), 老配置文件缺这个字段时自动得到 false。

2.2 单一收口

// applyFormInner(2271)白名单之后
if (form === "compact" && !(CFG && CFG.compactEnabled)) form = "panel";

按钮、Esc、Ctrl+2、旧配置、以后新增的入口,全部经过这里。它同时兜住"正在紧凑条时把开关关掉"的情况: 下一次几何调用会落成面板。

2.3 顶栏按钮

关闭时 #btnC 直接 display:none,不是变灰禁用(需求原话:「不显示这个按钮」)。 但同一位置要换成「胶囊」按钮(#btnPill)—— 否则关闭紧凑条后,胶囊只剩 Esc / Ctrl+3 两条看不见的路径,用户会以为胶囊也没了(v0.1.64 的真实回退,见 §10.1)。 开启时反过来:显示「紧凑」、隐藏「胶囊」。两枚按钮由 body 类互斥,顶栏始终只有一个折叠入口,宽度不变。

body:not(.compact-on) #btnC{display:none}
body.compact-on #btnPill{display:none}

实现上用 body 类而不是内联样式:配置还没读回来时按钮也默认是「胶囊」,不会先闪一下。 新增 applyCompactUI() 切换 body.compact-on,在 applyConfigToUI()(app.js:3935)和开关回调里各调一次。 开启后立即出现,不需要重启。

2.5 不删代码

紧凑条的渲染、fitCompact、条尾「▲ 展开 / ● 收成胶囊」、Ctrl+2 分支都保留。 开关只是入口闸门 —— 关掉再打开,行为与 v0.1.63 完全一致,也不会多出一套需要同步维护的"精简版"。

4. 升级与迁移

  • 新装:配置里没有这个字段 → 默认 false,顶栏只有「刷新 / 置顶 / 隐藏」。
  • 升级:老配置同样缺字段 → 一律 false。若上次停在紧凑条(CFG.form === "compact"): 启动本来就是面板(app.js:5984-5986),所以看不到"被卡在紧凑条";但顶栏按钮的消失会像功能被删了。 处理:启动时检测到这种组合,弹一次提示 ——「紧凑条已改为可选:设置 → 显示 → 启用紧凑条」, 同时把 CFG.form 清成 "panel" 并保存。下次启动不再提示。 不需要新增"提示已展示"字段:清掉 form 本身就是一次性标记。
  • 不改老用户的开关为"开":需求是默认关;用一次紧凑条不等于要永久开启, 自动打开会让开关状态取决于一个陈旧值,反而更难解释。
这是本次唯一会让老用户"少一个按钮"的地方。 所以提示里必须给出路径(设置 → 显示),只说「已改为可选」等于让用户自己去找。

8. 验收

  1. 全新配置:顶栏是「刷新 / 置顶 / 胶囊 / 隐藏」,设置里「启用紧凑条」为关;点「胶囊」能进胶囊,`▲` 能回面板。
  2. 打开开关:按钮立即出现,不重启;点它能进紧凑条;Ctrl+2 能进;Esc 走完整一圈。
  3. 关闭开关:按钮立即消失;Ctrl+2 无反应;Esc 面板 ↔ 胶囊;当时若在紧凑条,立即回面板。
  4. 旧配置 form:"compact" 升级:启动是面板,出现一次提示;重启后不再提示,CFG.form 已是 panel。
  5. 吸附:关闭时收起竖条不受影响、展开是面板;开启时展开紧凑条照旧。
  6. 开关落盘:重启后保持;手动把配置里的 compactEnabled 删掉则回到关。
  7. 胶囊 / 字号 / 置顶 / 吸附 / 其他开关行为不变;jsdom-smoke 与三形态回归通过。

9. 明确不做

不做为什么
删掉紧凑条代码、样式或快捷键分支开关打开后要完全恢复;删了就得维护两套渲染路径
把胶囊也做成开关本次只要求紧凑条;胶囊是"只看最紧一个"的唯一形态,价值不同
托盘菜单加入口形态切换已在顶栏与快捷键里;托盘菜单只放显示/刷新/退出
恢复"上次形态"启动现状就是启动面板;这属于另一个产品决定,不和本次混在一起
自动为老用户打开开关见 §4;默认关是需求,提示负责找回

10.1 复核修正:v0.1.64 关掉紧凑条后胶囊没有入口

v0.1.64 按"不显示紧凑按钮"实现后,顶栏只剩「刷新 / 置顶 / 隐藏」——胶囊还能用 Esc / Ctrl+3 进, 但没有任何可见入口。用户反馈:「只是紧凑不显示,胶囊还要有啊,现在也没法切换到胶囊了。」

修正:关闭紧凑条时,同一位置显示「胶囊」按钮(点击收成胶囊,`▲` 回面板);开启时显示「紧凑」。 两枚按钮互斥,顶栏宽度不变(特大字号实测 scrollWidth 492 = clientWidth 492)。 设置文案同步改成「关闭后顶栏改为『胶囊』按钮」。

复核:jsdom-smoke 58/58(新增顶栏胶囊入口);无头 Edge 10/10: 默认胶囊可见 → 点击进胶囊 → `▲` 回面板;开启后按钮互换;特大字号开关两种状态都不溢出;旧配置升级仍是面板 + 胶囊入口 + 一次提示。
