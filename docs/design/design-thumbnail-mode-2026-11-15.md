# 窄窗双列缩略详细设计

2026-11-15 用户选定窄窗双列缩略方案。本文件记录开发规格，初步比较见产品方案。

## 入口与配置

底栏及显示设置都提供「单列 / 双列 / 缩略」三段选择，每个按钮直接选中目标布局。当前项常亮，并提供 aria-pressed。配置 panelLayout 新增 thumbnail，旧配置继续默认 single，非法值回退 single。

缩略和单列共用 480×820 内容逻辑尺寸，字号倍率为 1、1.15、1.3。双列使用现有 860×820 尺寸。透明边距每侧 10px，尺寸和屏幕边界处理复用现有窗口管线。

底栏保留 AI 优惠、布局切换、设置和更多。退出放进更多菜单，Escape 关闭菜单。低频更新提醒仍使用现有入口。

## 页面与卡片

| 区域 | 标准字号预算 |
| --- | --- |
| 标题栏 | 44px |
| 临期积分、最早到期、签到三格摘要 | 64px |
| 当前渠道数与数值口径说明 | 24px |
| 卡片网格 | 两列，间距 8px，横向边距 14px |
| 单张卡片 | 约 220px 宽，默认高 80px |
| 底栏 | 40px |

14 个渠道共 7 排，卡片及排间距 608px。网格上下内边距 16px，全页预算 796px。沿用用户排序，从左到右、从上到下呈现，异常只改变提示与颜色。

每卡顶部使用 18px 官方图标和 12px 名称，图标缺失沿用现有字母兜底。中部以 22px 数字呈现余额或配额，金额保留币种、积分保留单位、百分比保留主窗口标签和已用/剩余口径。底部使用 12px 单行关键状态。字体与间距均随字号倍率缩放。

WorkBuddy AI、Qoder 国内版使用能区分版本的名称。Google Cloud 小卡短名使用 Gemini · GCP，完整名称在辅助提示及详情呈现。长名称单行省略，金额优先通过缩小至 14px 保持完整，极长内容提供全文辅助提示与详情。

## 数据与状态

卡片复用 renderRow 的主余额和状态输入，按 key 进行 DOM 更新。新增缩略摘要只在面板缩略布局生成，避免隐藏的重复文案影响其他形态。

| 情况 | 主数值 | 底部摘要 |
| --- | --- | --- |
| Codex | 主窗口百分比和窗口标签 | 5 小时百分比、重置卡数；耗尽时附恢复时间 |
| Antigravity | 后端选定主窗口百分比和窗口标签 | Gemini 5 小时余量、实际限流窗口恢复倒计时；完整模型组写入辅助提示 |
| 其他配额 | 现有主周期百分比 | 周期与重置倒计时 |
| 积分 | 完整余额与单位 | 最近一笔到期日期和金额，缺失明细时明示未知 |
| API 金额 | 现有金额和币种 | 现有告警、限流、申请制风险或今日消耗 |
| Google Cloud | 现有 USD 赠金余额 | 复用赠金日期规则与来源提示 |
| 读取失败且无旧值 | 破折号 | 读取失败和原因 |
| 失败或陈旧且有旧值 | 带 ~ 的旧余额 | 数据已旧和失败说明 |
| 真实零余额 | 0 及单位 | 对应渠道的真实状态 |

原来的完整状态轨、签到状态、日期和说明保留在详情及辅助提示中。限流、登录失效和陈旧状态优先于普通状态。正常额度不增加装饰性色彩，异常同时提供文字。

倒计时加入现有分钟 ticker。跨过重置时间显示待刷新，固定时钟夹具与固定数据使用同一时基。刷新不改变卡片高度或重复创建节点。

## 可用高度与数量

网格读取真实可用高度，扣除上下内边距、失败横幅和签到提示条，再计算两列所需排数。卡片高度在 68–80px 的字号倍率范围内调整。正常 14 渠道以 80px 呈现，15–16 渠道可收紧卡片。达到最小高度后允许滚动，标题栏、摘要和底栏保持可见。

渠道数取实际可见列表。临期筛选显示「显示 N / 总数 个渠道」，关闭筛选后恢复完整集合。隐藏和未配置渠道沿用原有过滤条件。

遇到屏幕工作区钳制时以实际列表高度为准。验收记录窗口逻辑尺寸、字号倍率、scaleFactor、列表可用高度及末卡位置，当前本机 14 渠道应全部一屏可见。

## 交互与失败路径

点击或按回车打开现有渠道详情弹层，关闭时恢复原卡片焦点。卡片本身保持固定高度。详情内的配置、历史和各模型窗口继续使用既有入口。

布局保存期间三段按钮暂时禁用，防止并发写入。保存失败恢复前一个布局和选中项，并显示失败提示。保存成功后应用目标窗口尺寸，异常时提供窗口切换失败提示。重启由已存 panelLayout 恢复。

## 模块与验证

- panel-layout.js 负责布局白名单、选择和回滚、缩略摘要、真实高度适配。
- panel-layout.css 负责三段选择、更多菜单与缩略形态，样式以 form-panel.layout-thumbnail 为边界。
- app.js 保留窗口尺寸入口、行渲染接线和分钟 ticker 接线。
- core/config.rs 接受 thumbnail 并验证序列化与非法值回退。
- thumbnail-regression.js 在 jsdom-smoke 初始化完成后串行执行，覆盖动态渠道、多窗口、口径、节点焦点、保存成功与失败。漏行坏样本验证断言会报红。
- 浏览器排版使用真实渲染得到的合成夹具，覆盖三档字号、深浅主题、屏幕高度钳制和更长数值。卡片高度超限和单列网格坏样本必须报红。

浏览器排版检查属于开发期验证，使用 Python Playwright 与系统 Edge，安装方式为 python -m pip install playwright。布局夹具由 THUMBNAIL_LAYOUT_FIXTURES 环境变量指定 jsdom-smoke 的输出路径，然后执行 python build/verify-thumbnail-layout.py <夹具路径>，可选 --screenshot <本地PNG路径>。凭据与用户配置不写入夹具。CI 使用现有 jsdom 冒烟和静态门。
