5. 对下一步（P0）

  1. Esc 已经存在，别把它当新增。P2 的键盘项要做的是"补齐到三种形态 + 加聚焦导航"， 顺带解决一个现状问题：Esc 现在到不了紧凑条，而紧凑条是用户待得最久的形态。 循环顺序需要一个拍板（建议 panel → pill → compact → panel）。
  2. daysOfBalance 不是"深挖"，是"搬家"。它已经在折叠行里了（claim-warn）； P0 要做的只是把它从"某个 UI 片段"提升为视图模型里的 eta_secs 字段，四种形态各取所需。 这比从零接入便宜得多。
  3. 七态状态机要接管的，恰好是今天被 CSS 分着藏的那一批。 styles.css:492-502 一口气藏掉了 bar / use / wins / exps / caret / rbody / claim-warn / win-warn / nm .s / val .p / rhead .rhint 十一项 —— 这就是"四种形态各说各话"的物理位置。 view.rs 落地时可以直接拿这份名单当回归清单：某一个字段在形态 A 里可见、在形态 B 里消失， 必须是一次显式决策，而不是一次 CSS 兜底。
  4. 吸纳修正后的事实再做一次自检。尤其 D13：claim-warn 在折叠行可见，说明"面板折叠行"其实已经承载了 §2.2 说的九样元素；P1 的两级行方案需要明确回答"第三段去哪里"——留给展开区，还是降级到悬停。
