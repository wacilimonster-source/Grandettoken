桌面设置现在根据已记录的 401 提示重新授权。授权完成时核对当前 Gist 的所有者，凭据替换与发布共用锁。保存登录状态失败时恢复原凭据。自动发布开启且已到期时，授权成功后立即安排发布。待发密文按原序号重试。

现场恢复需要在浏览器确认 GitHub 设备授权。授权完成后可通过桌面发布状态和同一 Gist 的匿名读回确认新快照，再核对手机刷新结果。

## 11 月 27 日补回桌面应用标识

旧安装版的编译环境和本机同步配置都缺少 OAuth Client ID，重新授权因此在申请设备码前停止。GitHub 开发者设置仍有 Grandettoken Desktop 应用。用它的公开 ID 申请设备码返回 200。本机通过原同步设置保存了该 ID，并读回确认已生效。

桌面源码内置该公开 ID 作为默认值，保留原有本机配置和构建变量的覆盖优先级。移除默认值后，未配置构建变量与本机配置的用例按预期失败。还原后串行通过桌面 §4.1 门禁。

安装版已从同步设置完成设备授权并恢复发布。11 月 27 日 10:56（北京时间），匿名读回的在线快照与本机已提交的密文哈希一致，响应完整。同一请求经本机配置的代理返回 GitHub 403，匿名额度为零。手机的实际刷新结果待按其网络和诊断信息核对。
