## ❌ 失败 1:Android 小组件标签的括号全半角不一致(用例侧腐化)

**用例**:`WidgetFormatterTest.emits_short_window_tags_from_stable_keys`(`android/app/src/test/.../widget/WidgetFormatterTest.kt:89`)

```
expected: 月额度（按套餐周期）     ← 用例期望:全角括号
 but was: 月额度(按套餐周期)      ← 实现 (WidgetFormatter.kt:153):半角括号
```

**根因**:v0.3.14(`0385c63`,「全端文案统一与错误提示收编」)在提交说明里明确宣布了标点基线 ——
**「标点基线(句中半角)收编 PC/Android/Rust 全部用户文案」**。实现 `WidgetFormatter.kt:153`
按新基线用了半角括号;同一次提交里写进的测试用例却仍是旧的全角写法。两份文件都诞生于
`0385c63`,**即这条测试从入库第一天起就没通过过** —— 说明 v0.3.14 的发版验证没有跑过
`:app:testDebugUnitTest`(Gradle 结果目录里的失败与此完全吻合,非环境噪声:其余 9 个测试类 31 例全绿)。

**判定与修法**:按 v0.3.14 自己定下的基线,**该改的是用例不是实现** ——
把 `WidgetFormatterTest.kt:89` 的期望改成 `"月额度(按套餐周期)"` 即可(一行)。
同时建议把 Android 单测纳入发版验证清单,否则「全端文案统一」这类改动在 Android 侧永远是零回归保护。

## ⚠️ 隐患 2:`build/probe-frontend.js`(假 DOM 探针)已腐化,与当前 app.js 不兼容

**现象**:`app.js:2605` `const trayBrand = new Image()`(托盘品牌图标)在探针的手搓假 DOM 里没有
`Image` 构造器 → 顶层执行当场抛 `ReferenceError: Image is not defined` → 脚本后半段从未初始化,
后续探针调用级联报 `Cannot access 'LOG_INFO' before initialization`(`LOG_INFO` 声明于 `app.js:6229`),
「排查日志卡」断言因此误报 FAIL。

**判定**:这是**工具腐化,不是产品缺陷** —— 真浏览器里 `Image` 是全局构造器,且维护中的冒烟
`jsdom-smoke.js`(jsdom 自带 `Image`)162 例全绿。该探针不在 CI 门禁里(CI 只对它做 `node --check`)。

**修法**(二选一):给探针假 DOM 补一个最小 `Image` 类(`onload`/`src` 可赋值即可);或直接退役,
冒烟职责已由 `jsdom-smoke.js` 承担。留着一个报假警的探针比没有更糟。
