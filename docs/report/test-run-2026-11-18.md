## 3. 唯一红项的完整调查链:`build/verify-refresh-stability.js`

> 此脚本**不在 CI 内**,是本地"真实排版 QA 工具"(无头 Edge 量首页刷新稳定性)。调查全程只读,符合「门禁红了先证伪门禁自己」(AGENTS.md §6.5)。

### 3.1 现象
- `node build/verify-refresh-stability.js` → `没拿到结果节点。DOM 尾部: ` exit 1。**DOM 尾部为空字符串**(stdout 0 字节)。

### 3.2 排除过程(每步有实测)
1. 脚本期待 `#list`/`__QA_RESULT`,而非 AGENTS.md 记载的旧 `.quota-number` —— 不是 §6.4 那种"引用已删选择器"的腐烂;脚本头也声明了开发期依赖。
2. 本机 Edge 存在,排除"找不到浏览器"。
3. 手动以脚本相同旗标 + 文件重定向(PowerShell `Start-Process -RedirectStandardOutput`)运行:**成功**,DOM 706KB,`__QA_RESULT` 存在,`fatal: (none)`、`jsErrors: []`。
4. 二分旗标:`--virtual-time-budget` / `--disable-gpu+--no-sandbox` / `--disable-extensions+--disable-background-networking` / `--window-size+--force-device-scale-factor` **各自单独加都成功**;完整旗标集连跑 3/3 成功 → 排除旗标本身。
5. 用 node `execFileSync`(与脚本相同的管道捕获)跑同一命令:**stdout 0 字节,复现**。

### 3.3 定位结论
**根因:Edge 是 Windows GUI 子系统程序,对本机管道型 stdout(`execFileSync` pipe / msys 管道)不写 `--dump-dom` 输出(实测 0 字节、exit 0);只有文件/控制台句柄才正常写。** 脚本用 `execFileSync(..., { stdio: ["ignore","pipe","ignore"] })` 捕获,在这台机器上必然拿空 DOM → 必然红。与业务代码、页面渲染无关。

### 3.4 底层业务内容验证(证明工具要量的东西是好的)
经文件重定向取得完整 `__QA_RESULT`:
- **19 个场景全部完成**,无 fatal、无 JS 错误,`ghostPeak` 全 0(无布局抖动);
- 场景覆盖:相同数据连续刷新、数字跨位数、正常→失败→陈旧→告警四态迁移、状态轨/进度条出现、两类警告消失、**真实重排与平局稳定**、新增/移除渠道、临期筛选、连续快速刷新;
- 数据含真实几何(卡片/头/数值/徽标矩形)、`vFont: tabular-nums`、`vColor` 等排版细节。

### 3.5 分类与建议(供审查 agent 裁决,本轮未改)
- **分类:环境级工具问题(§6.4 形态的变体:工具自身的捕获管道失效),不是产品回归,不是门禁误报业务问题。**
- 建议(下次动工时):① 该脚本把 Edge stdout 改为重定向到临时文件再读,stderr 不要 `ignore`(本次调查慢就慢在 stderr 被丢);② 调查中还观察到一次偶发 `Multiple targets are not supported in headless mode`(chrome_main.cc,Edge 中国版后台 importer/身份服务抢建第二 target 撞上 headless 初始化),文件重定向 7 连跑仅 1 次 —— 若改文件重定向,顺手加一次"空输出即重试一次"即可覆盖;③ 可考虑在 AGENTS.md §6.7 追加一条本机 Edge 管道捕获的注意事项(**本报告只提议,未改 AGENTS.md**)。
