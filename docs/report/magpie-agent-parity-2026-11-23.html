0. 说人话的结论

  • 粒度不同，目标相同。magpie 把每个 agent 拆成一组可读写「字段」（model / small / effort…），置空 = 断开；我们是「整块写入 + 取消写入」。两者都保注释、都原子写、都读回校验、都要预览确认 —— 这几条我们已经和它一致。
  • 三处实质差异，且 magpie 明确踩过坑： ① 我们给 Claude Code 写 env.ANTHROPIC_MODEL，它会压掉用户在 /model 里的选择（magpie 注释：旧版这么写，选择只活一个会话，已移除）；magpie 改写顶层 model + 分层 env。 ② Codex 登录 ChatGPT 时 magpie 只改 openai_base_url、保留内置 provider 与登录态；我们一律换 model_provider，会弄丢它自己的模型、线程与 /model 选择器。 ③ magpie 不因「agent 在跑」拒写（Windows 上它认为问不到进程，索性总答「在跑」），改为写后提示「重启 / 开新会话」；我们是在跑拒写。
  • 还原语义差一层。magpie 双层保护：首写前整文件拷贝（beforeMagpie）+ 值级 stash.json（断开时把用户原来的 endpoint / provider / model 还回去）。我们只有整文件 DPAPI 快照；断开时不还原用户原 model / provider（Claude 的 ANTHROPIC_MODEL、Codex 的 model_provider/model、OpenCode 的 model 都是直接删/重置）。
  • 发现与拼写我们写死了。magpie 认 OPENCODE_CONFIG_DIR/XDG_CONFIG_HOME、config.json 兜底、OpenCode 2 的 providers 拼写、CLAUDE_CONFIG_DIR、同名二进制甄别（binNot/goProgram）；我们路径固定、只认 OpenCode 1 的 provider。
  • 自愈与归因我们完全没有。magpie 有 Check（配置被别处改写时发现）+ Sync（把 magpie 块补回 / 模型目录同步）、按入站 User-Agent 区分是哪个 agent、按 agent 勾选可见模型、接入前告诉用户「它现在跑在什么上」（订阅/ChatGPT/自己的 key/N 个 provider）、卸载清残留。我们都没有。
  • 已经一致的：group/ 路由组前缀、单一网关密钥（magpie 也靠 UA 而非多密钥区分 agent）、保注释局部编辑、原子写 + 失败回滚、预览后才允许确认写入。

2. 分组清单

加跟随（magpie 有、我们缺，且与现有裁决不冲突）

  • Codex 登录态双模式 + provider 表保留 + 未知模型 stand-in（裁决 2）
  • 值级 stash：断开还原用户原 endpoint/provider/model（裁决 5）
  • Check 漂移检测 + Sync 自愈（裁决 6）
  • 入站 UA 归因；每 agent 模型可见性（裁决 7）
  • Source 展示 + 改后重启 Notice（裁决 8）
  • 卸载 leftovers 清理（裁决 9）

补解析（发现/拼写/字段补齐，低风险）

  • OpenCode：OPENCODE_CONFIG_DIR/XDG_CONFIG_HOME、config.json 兜底、v2 providers 拼写、small_model（裁决 4）
  • Claude：CLAUDE_CONFIG_DIR、云开关检测、分层 about-env（裁决 1/4）
  • Codex：auth.json 登录态读取（裁决 2 的前置）

删独有（我们有、magpie 明确认定是坑而移除的）

  • Claude Code 的 env.ANTHROPIC_MODEL 写入（裁决 1）
  • Codex「取消写入即整段摘表」（旧线程会打不开）（裁决 2）

待确认保留（与 magpie 不同，但可能是我们自己的产品/安全决定）

  • 在跑拒写（magpie 不拦）—— 涉及已披露安全前提（裁决 3）
  • DPAPI 整文件快照（magpie 用内存快照 + 首写拷贝）—— 已披露能力，建议保留作兜底（裁决 5）
  • 品牌命名 grandettoken / GW-（不跟 magpie）（裁决 10）

明确不做（design §1 定位之外）

  • WSL 发行版内 agent、env-only 启动器/shell 函数、import-link 应用、插件新增 agent、telemetry/advisor/auto-mode 字段、上百 CLI 扩展（裁决 10）

3. 编号裁决项（每项给替代改法与代价）

1 · Claude Code 模型写入口径

现状：写 env.ANTHROPIC_MODEL（inject_cli.rs:198/207）。magpie：该键压掉 /model 选择，已移除；改写顶层 model + 分层 env，接入期间暂存用户原值、断开还回（claude.go:31-74）。

A 跟随 magpie（推荐）：写顶层 model + DEFAULT_{OPUS,SONNET,HAIKU}_MODEL + SMALL_FAST + SUBAGENT；不写 ANTHROPIC_MODEL，若用户原有则暂存并在断开还原。代价：写入键从 3 个变 7+ 个，预览/回滚/单测都要扩；分层模型选同一个还是按层选需再定（默认全同）。
B 保持现状：继续三键。代价：用户在 Claude Code 里 /model 换模型只活一个会话，与 magpie 踩过的坑相同。
C 折中：顶层 model + 仅 SMALL_FAST/SUBAGENT，不动 OPUS/SONNET/HAIKU 分层。代价：/model 的 tier 切换仍不跟随网关模型，但主模型选择不再被压。

一句话否决：回「1B」即保留三键写法，本项不做。

2 · Codex 登录态双模式 + provider 表保留 + stand-in

现状：一律换 model_provider + 托管表，取消即摘表（inject_cli.rs:509/533）。magpie：ChatGPT 登录只改 openai_base_url；表写过就保留；未知模型用当轮模型顶替（codex.go:39-90）。

A 跟随 magpie（推荐）：读 ~/.codex/auth.json 判登录态选模式；表保留、只摘 model_provider；网关对 codex-auto-review 等名字用当轮模型顶替。代价：要新增登录态读取（涉及读登录文件，按 §2.4 需披露）；网关模型解析加 stand-in 分支；取消写入语义改变需同步 README/design。
B 保持现状：一律 provider 表。代价：ChatGPT 登录用户丢失自己的模型/线程/选择器；旧线程在取消后打不开。
C 折中：仍一律 provider 表，但表保留不摘 + stand-in；不做登录态双模式。代价：ChatGPT 自己的模型仍不可用，但线程与 review 不再坏。

一句话否决：回「2B」即不动 Codex 写入语义。

3 · agent 在跑时写不写（安全前提变更，单独过目）

现状：在跑拒写（inject.rs:777）。magpie：不拦写，Running() 只产出「重启/新会话」提示；Windows 恒答在跑（agent.go:415-435）。

A 跟随 magpie：去掉拒写，改后按 agent 给重启/新会话提示。代价：推翻 design F5 前提①与 README 披露；边跑边写可能被 agent 退出时覆盖（magpie 靠提示让用户重启规避）；需同步改文档与门禁哨兵。
B 保持现状（安全优先）：在跑拒写。代价：与 magpie 方式不一致；用户必须先关工具才能接入（本次实机即如此）。
C 折中（推荐）：在跑仍允许写，但强制「预览 + 二次确认 + 写后重启提示」，并保留 DPAPI 快照兜底；未跑时流程不变。代价：多一次确认交互；文档把前提①改述为「在跑需二次确认」。

一句话否决：回「3B」即保留在跑拒写，本项不做。

4 · 配置发现与拼写补齐

现状：路径写死、只认 OpenCode 1 provider、文件只到 jsonc/json。magpie：env 目录优先、config.json 兜底、v2 providers、CLAUDE_CONFIG_DIR、同名二进制甄别（agents.go:1455-1467、agent.go:408-434）。

A 全补（推荐）：env 目录 + config.json 兜底 + v1/v2 拼写按文件实际形状读 + CLAUDE_CONFIG_DIR + 同名甄别（binNot 思路：校验二进制归属）。代价：发现逻辑变复杂，需为每种形状补坏样本单测。
B 只补目录与兜底：env 目录 + config.json，不动拼写与甄别。代价：OpenCode 2 用户仍写错位置（写进 v1 的 provider 而它读 providers）。
C 保持现状。代价：自定义目录/OpenCode 2/同名工具场景接入失败或误判。

一句话否决：回「4C」即不动发现逻辑。

5 · 断开还原语义（值级 stash）与首写保护

现状：整文件 DPAPI 快照；取消写入不还原用户原 model/provider。magpie：stash.json 值级原值 + beforeMagpie 首写拷贝 + edit.Atomically 内存快照（stash.go:17-30、agents.go:1543-1577、edit/file.go:332）。

A 纯 magpie：改用内存快照 + 值级 stash，去掉 DPAPI 落盘快照。代价：失去已披露的「加密备份可一键回滚」能力，跨会话/崩溃后不可回滚；不建议。
C 双层并存（推荐，= magpie 语义 + 我们的兜底）：新增值级 stash（记接入前 endpoint/provider/model 及各 env 原值），断开优先还原原值；DPAPI 整文件快照保留作崩溃/误操作兜底。代价：stash 需加密或至少不写明文密钥（只存 endpoint/model/provider 名，不存 key）；两套还原路径都要单测。
B 保持现状：只有整文件回滚。代价：断开后用户原来的模型选择丢失（magpie 明确要还回去）。

一句话否决：回「5B」即不加 stash。

6 · 漂移检测 Check + 自愈 Sync

现状：无。magpie：model 仍是 magpie 的但 wiring 被改 → 报漂移；Sync 只在已接入时把 magpie 块/目录补回（agent.go:271-279、agents.go:1300-1310）。

A 补 Check+Sync（推荐）：界面显示「配置被外部改动」并给一键修复；Sync 只补我们写过的块，不碰用户其它内容。代价：每次打开面板多读几个文件；需坏样本（手改配置）单测。
B 只 Check 不自愈：提示漂移，修复靠重新写入。代价：用户多一步操作，但不会自动改文件。
C 不做。代价：配置被别处改写后界面仍说「已接入」，请求实际绕开网关。

一句话否决：回「6C」即不做漂移检测。

7 · 入站 UA 归因 + 每 agent 模型可见性

现状：台账只有渠道/模型；可见性只到渠道级。magpie：入站 UA 前缀认 agent；HiddenModels/PickedModels 按 agent 过滤（settings.go:1146-1158）。

A 两者都补：台账加 agent 列（按 UA）；接入面板加「该 agent 可见模型」勾选。代价：台账 schema 再迁移一次（v7→v8）；UA 可伪造，归因仅作展示不作鉴权。
C 先只补 UA 归因（推荐）：台账/诊断加 agent 归属；可见性后议。代价：仍需一次 schema 迁移；可见性差异保留。
B 都不补。代价：多 agent 共用网关时分不清谁在花钱、谁绕开了网关。

一句话否决：回「7B」即不做归因与可见性。

8 · 接入前 Source 展示 + 改后重启 Notice

现状：预览只列文件与动作；无重启提示。magpie：Source() 显示 sub/chatgpt/key/providers:N；Notice() 按 agent 给重启建议（connectinfo.go:20-33、agent.go:141-143）。

A 补两者（推荐）：预览顶部加「它现在跑在：…」；写入成功后按 agent 显示「重启 X / 开新会话生效」。代价：读登录态文件（与裁决 2 同源，需一并披露）；提示文案要按 8 客户端维护。
B 只补 Notice：不读登录态，只给重启提示。代价：用户仍不知道接入会顶掉什么。
C 都不补。代价：改完没提示，用户以为没生效（magpie 注释里 Windows 静默丢提示踩过的坑）。

一句话否决：回「8C」即不加展示与提示。

9 · 卸载清残留

现状：卸载不清外部客户端里我们写过的网关地址。magpie：TakeLeftovers 在卸载时摘掉「指向已消失网关」的配置（agent.go:254-260）。

A 补（推荐）：卸载流程里对 8 客户端摘除我们写过的托管块/键（保留用户其它内容），失败不阻断卸载。代价：卸载器要能调 Rust 清理逻辑或 NSIS 脚本调 exe 子命令；需单测 + 真机卸载验收。
B 只提示不自动清：卸载完成页列出「这些工具里还留着网关地址，手动移除方法」。代价：残留仍在，agent 会对着死网关重试。
C 不做。代价：卸载后外部 agent 持续报错重试。

一句话否决：回「9C」即不清残留。

10 · 明确不做组 + 品牌命名保留

magpie 的 WSL 发行版内 agent、env-only 启动器/shell 函数、import-link 应用、插件新增 agent、telemetry/advisor/auto-mode 字段、上百 CLI 扩展，与 design §1「Windows 轻桌面挂件 + 现有 5 IDE + 3 大编码 CLI」定位冲突。

A 确认不做 + 保留自有品牌（推荐）：provider id 继续 grandettoken、显示前缀 GW-、模型 alias/model 与 group/<id>（group/ 前缀本就与 magpie 一致）。代价：与 magpie 配置不互通（用户从 magpie 迁过来需重接），属预期。
B 部分跟随：只补 env-only 启动器（给只认环境变量的 CLI 一条启动命令），其余不做。代价：新增一类接入面，需披露与维护。
C 品牌也跟 magpie：provider id 改 magpie。代价：与上游产品撞名、已写入用户配置的 id 需迁移；强烈不建议。

3b. 实现偏差清单（2026-11-23 开发轮，相对 magpie 与裁决卡）
