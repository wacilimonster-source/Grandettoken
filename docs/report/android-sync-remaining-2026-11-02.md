## P0：先保证数据和发布安全

### 1. 近期历史没有按设计完整同步

**现状：** `app/core/src/sync/builder.rs` 的 `build_history` 读取 `daily_summaries`，并把每个历史点的 `balance` 固定为 `None`。这不能保证把 PC 最近 7 天明细快照中的余额/消耗正确带到手机；手机详情即使有图表，也可能显示无数据。缺失点使用当前时间作为 `revised_at` 的行为，也需要检查是否会在跨来源合并时覆盖真实记录。

**任务：**

- 对照 PC 已有快照、归档摘要和多账号/密钥指纹分段逻辑，设计并实现最近 7 个自然日的余额与消耗发布。不能把不同账号、不同币种或不同来源的数据拼成一条虚假历史。
- 保留缺口：没有观测时 `balance`/`spent` 保持 `null`，不要补零；区分确有零消耗与采样不足。明确时间戳、时区、同日修订和跨来源去重口径，并同步协议文档/fixtures。
- 验证发布内容仍满足字段白名单，不包含密钥、指纹、账号、原始错误或本机路径。

**验收：** PC 有近 7 天记录时，手机显示对应真实历史；缺失天在图上断开；无数据、跨日、充值、换密钥、不同币种和两台电脑同渠道合并均有测试。用用户允许的测试数据检查端到端，不要输出真实同步码或余额到日志。

**完成记录（2026-11-02）：**
- `build_history` 改为从最近 7 天**明细快照**计算：`balance` 取当天最后一条成功快照；`spent` 今天取 `ChannelView.day`，历史日按当前 key 指纹用 `consumed_in_window_fp` 的余额差规则；不再用 90 天归档后的 `daily_summary` 冒充最近一周。
- 新增 `Store::last_snapshot_between`；`HistoryPoint.complete` 标记采样缺口；`revisedAt` 只用真实观测时间，缺失日用当天零点，不再用 `now`。
- 多本账按当前 key 指纹分段；`accounts > 1` 且取不到当前指纹时整段历史为空，避免拼账户。
- 契约与 fixture 已更新；Rust 398 项单测 + 6 项 fixture 通过；Android 18 项单测/构建通过。
- PC 本机真实数据预览：9 个渠道均返回 7 天 history，余额点 7/7；消耗/完整点 6–7 天（今天或个别采样缺口为 null），未输出任何余额或同步码。
- 待手机端发布后确认图表实际展示；未做卸载/重装，未动 MuMu 数据。

## P2：补齐设计稿中的功能和异常状态
### 5. 手机 GitHub 可选登录与刷新设置

- Android 目前匿名模式可用，“登录 GitHub 提速”仍是说明弹窗。按设计使用**独立手机 OAuth App** 的 Device Flow，不请求桌面 `gist` 写权限；手机匿名使用必须继续可用。
- 补齐授权取消、过期、限流、401、重新授权、断开及安全存储；验证 Secret Gist 的匿名与登录只读行为。前台刷新策略、后台关闭/15/30/60 分钟等选项按设计实现并说明系统限制。
- 验收：匿名、登录、拒绝授权、断网和限流均有正确退避与状态；手机不创建或修改 Gist，不要求用户填写 PAT。

**完成记录（2026-11-02，客户端）：**
- 设置页接入 Device Flow：可填写公开 Client ID（用户选择 b，可填桌面 OAuth App 的同一 Client ID；也兼容将来换独立手机 App），device_code 只留在内存，token 只存 Keystore 密文。
- 授权严格校验零 scope：返回任何额外权限（包括 `gist`）都不保存 token；保存前再用 token 实际读取当前 Gist，失败则保留匿名模式。
- 支持取消、过期、`slow_down`、拒绝、401、限流；401 自动清 token 并回退匿名，断开登录清 token/登录名但不退出同步组；前台按登录状态 60 秒 / 匿名 5 分钟，后台 15/30/60 分钟。
- 当前桌面配置没有可直接读取的 Client ID，手机首次登录需要粘贴同一个公开值；未用真实 Client ID 完成端到端授权验收。

### 6. 通知、诊断和数据管理

- 按设计实现余额预警、长时间未更新、同步失败通知及开关；处理 Android 通知权限、去重和恢复，避免限流/网络错误反复打扰。
- 完善组状态与诊断：最近成功读取、来源解密失败、冲突和可操作的错误状态；手机用户界面不展示设备名或写入者标识。实现清缓存、更换/退出组并清楚说明对本机和远端的影响。
- 验收断网、404、403/429、截断、部分来源解密失败、无缓存、时钟异常、重复通知和退出/恢复。错误状态保留最后可信快照，不把缺失数据当零。

**完成记录（2026-11-02，客户端）：**
- 通知默认关闭；开启时申请 Android 13 通知权限，并提供系统通知设置入口。余额提醒：金额型 CNY ≤ ¥10、配额型 ≤ 20%；数据过期：超过 2 小时或有错误码；同步失败：连续 3 次。同一渠道同类提醒 6 小时内不重复，通知不含具体余额或账号。
- 前台刷新、加入同步组和 WorkManager 后台刷新共用同一套通知与失败计数；限流不触发失败提醒。
- 诊断改为只显示失败来源**数量 + 错误码**，不再显示 source ID；Gist 错误去掉文件名，网络错误不再拼接原始异常文本；新增「最近成功读取」。
- 设置页新增清除本地缓存（保留同步组和登录，删除缓存/ETag/序号水位），退出同步组说明重新扫码即可更换同步组。
- 规则单测覆盖阈值、过期和失败次数；未做真机通知权限/锁屏展示验收。
