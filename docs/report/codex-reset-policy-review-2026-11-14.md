# 重置卡推荐规则与实现复核

## 独立推荐规则

目标按优先级排列为满足明确的使用期限、保留可用额度、减少不必要兑换、减少有实际用途的卡过期。推荐输出应包含动作、触发原因、恢复时间、可用卡、兑换资格和估算假设。

1. 先确认账号、数据新鲜度、窗口数据一致性、库存和最近兑换回写。数据不能支持结论时给出具体待确认条件。
2. 明确使用期限。「现在」表示不能等待，「今天」表示能等到本地当天结束，「能等」接受自然恢复，「暂时不用」没有当前兑换需求。省卡偏好不能覆盖明确期限。
3. 分别检查实际存在的额度窗口。周额度与五小时额度是两种不同的百分比，周额度用量不能直接换算成五小时用量。任何耗尽的必要窗口都可能阻止使用。
4. 比较全部受限窗口的自然恢复时间与使用期限。能在期限内恢复时优先等待，卡临期同时提示风险。今天能恢复时，卡临期本身不会把等待改成必须兑换。
5. 当前剩余够用时保留卡。只有期限内供给不足且重置能恢复当前瓶颈时，才推荐兑换。现在必须使用时，即使几分钟后就恢复也尊重需求，并显示等待的免费替代和用卡代价。
6. 兑换前核对卡的涵盖范围和资格。手动使用要求至少一项涵盖额度剩余不足 80%。涵盖范围未知时给条件式结论。五小时已耗尽且卡仅恢复周额度时，明确这张卡无法解决当前瓶颈。
7. 多张适用卡优先使用最早到期的一张。到期时间是兑换截止，恢复后的额度遵循自己的周期。每次兑换后重新取数，再考虑下一张。
8. 计划使用事件模拟，分别处理自然恢复、额度耗尽、卡过期与订阅结束，用卡后更新恢复锚点。给出等待与兑换的供给差异，避免把恢复到 100% 的总量当成净增量。
9. 有订阅截止时使用该截止，无日期时按用户要求规划至最后一张有效卡到期并提示订阅持续有效的假设。各卡自己的有效期仍逐张检查，未知日期不构造无限供给。
10. 长期用量以历史或当前周期速度估算，显示样本与适用范围。缺少五小时工作量模型时，计划明确标注周额度供给范围，即时建议单独检查五小时瓶颈。
11. 账号、需求、用量、恢复时间、卡明细和时钟变化后重算，保存失败回滚，兑换回写期间阻止连续推荐。

官方规则包含手动兑换的 80% 门槛、各套餐完整重置的涵盖范围、已满窗口保留原周期，以及兑换截止与恢复后周期的区别。[OpenAI 帮助中心](https://help.openai.com/zh-hans-cn/articles/20001498-how-resets-work-in-codex)

## 与现有实现比较

| 项目 | 现有实现 | 本轮优化 |
|---|---|---|
| 现在必须使用 | 一小时内强制建议等 | 尊重现在需求，临近恢复作为代价提示 |
| 今天能够恢复 | 临期卡分支可能提前建议兑换 | 先判断能否在需求期限内恢复 |
| 五小时耗尽 | 仅作提示，周额度满时保留卡 | 检查瓶颈、自然恢复与套餐涵盖范围 |
| 兑换资格 | 两窗口均高于门槛仍输出 NOW | 已确认不符合时保留，范围缺失时提示核对 |
| 任务够用文案 | 只看周额度却声称整个任务够用 | 明确周额度口径，提示五小时工作量未估算 |
| 计划净收益 | 由当前空窗推算，未比较锚点移动后的供给 | 比较相同规划范围内等待与现在兑换的供给 |
| 计划范围 | 表述为全程不断 | 标注周额度试算及估算条件 |
| 周期/卡/账号隔离 | 已有独立字段与校验 | 继续复用并补交叉回归 |

本轮在独立即时判定模块中实现优先级，沿用现有持久化、IPC、计划模拟与 UI 入口。五小时需求量当前没有输入，采用耗尽状态识别确定瓶颈，正剩余时明确需要核对实际工作量。套餐未知时涵盖范围保持未知。

## 实现与验证

- `codex_reset_decision.rs` 实现期限、双窗口瓶颈、套餐完整重置范围、库存和资格判定。主模块继续做数据校验、账号输入、计划与文案输出，原因类型仍由编译器穷举检查。
- 满额以 100% 判断，99% 剩余不再自动遮住实际用量缺口。明确「现在」允许在符合资格时推荐兑换，一小时以内显示免费恢复的代价提示。「今天」优先等待能够满足期限的恢复，临期卡同时提示风险。
- 校验五小时百分比，已兑换待回写检查移到满周窗口分支之前。沿用原有 15 分钟常量作为快照过旧阈值，缺少时间的即时用卡建议要求先刷新。
- 「今天」需求在跨本地日界后失效，前后端一致。套餐信息进入建议输入与缓存指纹，前端冒烟读取真实保存的需求时间，避免午夜夹具误失效。
- 净收益比较同一截止下现在兑换与等待的周额度供给，允许显示负值。无可靠计划截止时比较到下次自然恢复。计划文案删除缺口除以卡数推导的每卡收益区间，并标注周额度试算范围。省卡策略的 25%/5% 阈值继续作为估算策略使用。

新增交叉回归覆盖 Plus/Pro/未知套餐、周额度满而五小时耗尽、今天能恢复且卡临期、五小时恢复后配合周重置卡、兑换资格、99% 实际缺口、兑换回写、快照过旧、跨日需求和负净收益。原规则中一小时强制等待、资格不足仍 NOW 的测试按新规则更新，日期清空与有效期回归继续保留。

本轮静态门与自检、JS 语法、CSS、原有 jsdom、顾问冒烟、核心全量、Tauri 全目标编译、凭据扫描均串行执行两轮并通过。核心全量使用 `cargo test --locked --quiet -- --test-threads=1`，避免仓库已记录的 proxy 内部并发不稳定。`git diff --check` 通过。
