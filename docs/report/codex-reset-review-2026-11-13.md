# Codex 重置顾问评审

2026-11-13，发布版本 v0.3.42。

## 评审范围与结论

检查未提交的 Rust 核心、Tauri 命令、前端模块、两份 HTML 原型及详细设计。详情页内展开、建议/计划/依据三页签、复用现有卡明细的方案通过评审。算法与持久化分层继续使用独立模块，主文件仅保留接线。

## 修正

- 已过期卡从可用数中扣除，避免被归入未知有效期后继续用于模拟。未知到期日的卡仅展示库存，计划采用已确认有效期的卡。
- 订阅过期优先返回保留卡。异常百分比、旧快照、刚用卡但缺少额度更新时间均停止给出用卡建议。
- 建议每分钟按当前时间重算，需求超过有效期后回到默认。缓存包含窗口和卡明细，计算失败会撤下旧结论。
- 每次重算读取当前账号设置，读失败清除旧设置。命令校验设置的账号指纹，拒绝换号后的迟到写入与计算。
- 保存期间禁用编辑，写失败回滚并提示。旧计算结果用序号隔离。
- 价值提示改为估算口径，周窗满额的说明与官方规则对齐。
- 模拟按订阅结束截断空窗，避免把订阅结束后的需求算成当前用卡收益。

## 设计文档中的算例差异

初稿写当前账本补满需要一张卡，严格连续使用模拟需要三张。因为每次用卡都会移动下一次恢复锚点，后续仍会产生空窗。省卡策略仍是零张，缺口约为一个周窗的 11%。该结论依赖平均速度与连续需求假设，刷新后的服务端恢复时间优先。

初稿把最早卡到期日作为整个计划截止会提前截断其他卡的效用。实现逐张处理有效期，计划截止使用手填订阅结束日。

## 官方规则复核

官方当前说明，手动使用预存重置需要涵盖的至少一项额度剩余不足 80%。已满 100% 的窗口保留原周期，至少恢复一项才消耗次数。界面增加兑换资格核对提示，5 小时窗口的实际兑换资格由 Codex 界面确认。[OpenAI 帮助中心](https://help.openai.com/zh-hans-cn/articles/20001498)

## 验证范围

零依赖静态门及自检、原有前端冒烟、顾问独立冒烟、core 全量测试、Tauri 全目标编译、凭据扫描均按 AGENTS 清单执行，输出为本次结果。顾问冒烟内置未知命令注入，必须触发断言失败，覆盖日期写失败回滚与设置读失败降级。

已用生产 CSS/JS 生成的模拟数据页面检查浏览器渲染。真实账号的兑换操作没有执行，安装包内 WebView2 的人工交互尚未验收。计划采用七天周窗与平均消耗速度，人工填写的订阅结束日按本地当日 23:59 计算。

发布记录与线上核验结果见 PROGRESS 文末本版条目。
