## 修正

- 已过期卡从可用数中扣除，避免被归入未知有效期后继续用于模拟。未知到期日的卡仅展示库存，计划采用已确认有效期的卡。
- 订阅过期优先返回保留卡。异常百分比、旧快照、刚用卡但缺少额度更新时间均停止给出用卡建议。
- 建议每分钟按当前时间重算，需求超过有效期后回到默认。缓存包含窗口和卡明细，计算失败会撤下旧结论。
- 每次重算读取当前账号设置，读失败清除旧设置。命令校验设置的账号指纹，拒绝换号后的迟到写入与计算。
- 保存期间禁用编辑，写失败回滚并提示。旧计算结果用序号隔离。
- 价值提示改为估算口径，周窗满额的说明与官方规则对齐。
- 模拟按订阅结束截断空窗，避免把订阅结束后的需求算成当前用卡收益。

## 设计文档中的算例差异

初稿写当前账本补满需要一张卡，严格连续使用模拟需要三张。因为每次用卡都会移动下一次恢复锚点，后续仍会产生空窗。省卡策略仍是零张，缺口约为一个周窗的 11%。该结论依赖平均速度与连续需求假设，刷新后的服务端恢复时间优先。

初稿把最早卡到期日作为整个计划截止会提前截断其他卡的效用。实现逐张处理有效期，计划截止使用手填订阅结束日。

## 2026-11-13 二轮：实机反馈修复

用户实机反馈：选择「现在就要」与「今天要用」时界面显示「暂时无法判断」。根因是 v0.3.42 的判定矩阵产出 `deadline_before_reset`（urgent/soon 且额度不够时的主路径），但 `reason_copy` 文案表没有这个分支，落进了 `_` 兜底。设计文档 §5.4 本来写了这条文案，实现时漏译——验证桩与静态门都测不出来：前端冒烟用 mock 应答建议命令，`check-ipc-contract` 只管命令注册。

修复与打磨（设计文档同步更新为 §4.4 v3）：

- `codex_reset::Reason` 穷举 enum + `reason_copy` 无兜底分支：文案表漏分支现在是编译错误，同类问题无法复发。全矩阵单测断言任何路径都不出现「暂时无法判断」。
- 新增 `RESET_IMMINENT_H = 1h`：距自然重置不足 1 小时且额度不够时 `wait/reset_imminent`，不为几分钟烧卡并把周窗锚点推走一周；此时卡若临期则带 `card_expiry_loss`。
- 「今天要用」以本地当天 23:59:59 为界（`AdviceInput.today_end_at`，命令层 `local_today_end` 按机器时区补齐，缺省退回 24h 口径）：修掉「晚上 22 点 + 明早 6 点重置被建议干等一夜」的误判。`soon` 的剩余够用时优先 `hold/remaining_covers`，不再被 24h 分支盖掉。
- `now` 且周窗与 5 小时窗剩余都 ≥80% 时发 `eligibility_unlikely`（官方资格口径：至少一项需不足 80%），替代通用核对提示。
- `card_expiry_loss` 触发条件从「patient/idle」放宽为「结论不是 NOW 且卡在重置前过期」——等或留的任何结论都该知道卡会作废。
- 前端落地设计 §5.3 的用量档位（少量 25% / 一半 50% / 整窗 100%）：urgent/soon 选中后展开，写入 profile 并参与判定；标了小用量且剩余够时不再劝烧卡。`inputKey` 纳入用量，建议随档位重算。
- 前端两处口径修正：删除从未被引用的 `REASON` 映射（死代码）；建议命令失败时标题显示「建议暂时不可用」而不是与后端兜底文案同形的「暂时无法判断」，两种失败从此可区分。

验证：core 全量 505 passed / 8 ignored；`src-tauri` 全目标编译通过；`verify-codex-reset.js`（含未知命令注入变红自检）与新增用量档位断言全绿。其余门禁见 PROGRESS 本轮条目。真实账号的兑换操作仍未执行。

## 2026-11-14 工作区复核

本轮开始时已有未提交的二轮修复，保留并继续复核。对照 HEAD 确认 `deadline_before_reset` 在判定路径中存在，在旧文案表中缺失，最终落到「暂时无法判断」。原测试只断言 verdict 与 reason code，前端测试返回自制文案，因此均漏掉了真实文案映射错误。当前工作区使用穷举原因类型与完整文案映射。

### 当前完整判定链路

1. 前端按当前账号加载需求与订阅结束日，构造周窗、5 小时窗、卡库存与更新时间。需求超过 12 小时回到「能等」。用量支持 25%、50%、100%，未选按 100% 估计。
2. 命令层检查账号范围，并补齐机器本地当天 23:59:59。核心函数使用传入时钟计算，前端每分钟重算，迟到的计算结果用序号隔离。
3. 先检查旧数据、订阅到期、周窗缺失、百分比矛盾、周窗接近满额、重置时间异常及刚兑换尚未回写。每项给出对应原因文案。
4. 比较自然重置与订阅结束。订阅结束前等不到重置时，明确需求且剩余不足才建议用卡，够用则保留，能等或暂时不用则保留。
5. 订阅允许等待时，临近一小时重置优先建议等待，「今天要用」还要求重置落在当天。有明确需求、剩余不足且卡会先过期时建议优先用临期卡。
6. 「现在就要」剩余不足则建议用卡，够用则保留。「今天要用」够用则保留，不够且当天能重置则等待，否则建议用卡。「能等」等待自然重置。「暂时不用」在重置一天内提示等待，其余保留。
7. 用卡建议需再通过库存检查。零张显示没有可用卡，未知或刷新失败显示卡数未知。到期明细用于排除过期卡，卡数冲突、有效期未知及兑换资格以提示呈现。周窗接近满额时保留卡，5 小时窗受限会提示去 Codex 核对涵盖范围。
8. 计划区独立按周平均消耗与订阅结束模拟，逐张处理有效期。每次用卡把下一次周窗恢复移到兑换后七天，避免重复叠加原自然重置。25% 省卡收益阈值、已产生空窗且卡临期时的 5% 阈值仅影响计划，速度滑块仅影响试算。有效期未知的卡不承诺计划供给。

一小时临近重置阈值沿用工作区现有策略，「现在就要」也可能得到等待建议，正文允许用户自行决定立即兑换。「今天要用」按当天结束理解具体期限。5 小时窗只参与提示与资格核对，当前用量与供给模拟采用周窗口径。这些都是产品策略假设。

### 本轮追加修正与回归证据

- 临近重置规则增加当天截止检查。构造今天剩十分钟、半小时后重置的用例，修复前错误返回 WAIT，修复后返回 NOW。
- 当天最后一秒仍接受当天截止值，避免回退到未来 24 小时。该用例修复前 WAIT，修复后 NOW。
- 卡刷新失败时旧库存按未知处理。构造带旧库存与 error 的用例，修复前 NOW，修复后 UNKNOWN/cards_unknown。
- 前端补充「今天要用」传参检查及用量写失败的回滚、可见提示检查。修正仅选择 urgent 才会 NOW 的提示和计划中把 soon 写成 urgent 的文案。

三个新增核心回归均先观察到失败，再修复并通过。静态门及自检、JavaScript 语法、原有 jsdom、顾问冒烟、core 全量、Tauri 全目标编译与凭据扫描的最终复跑结果记录在 PROGRESS 本轮条目。真实账号兑换及安装包 WebView2 交互仍待验证，本轮修改尚未发版。

## 2026-11-14 可选订阅到期日

本节记录首轮空日期交付，空日期的计划口径已按下节用户要求更新。

订阅到期日增加明确的「清空」按钮。按钮与日期输入在保存、计算期间禁用，空值禁用重复清空。沿用 `saveDate("")` 和 `clearSubEnd` 协议，命令层清除当前账号下的日期并保存，前端重新读取设置后计算建议。保存失败恢复原日期并提示，填写日期后可恢复计划。

| 日期状态 | 即时推荐 | 到期前计划 |
|---|---|---|
| 未填写或已清空 | 按用量、自然重置、卡库存与有效期计算，订阅能否等到重置显示未知 | 提示填写到期日，缺口为空，到期时间轴收起 |
| 未来且晚于自然重置 | 按需求判断用卡或等待 | 有足够消耗样本时计算 |
| 未来且早于自然重置 | 明确需求且额度不足时用卡，够用或能等时保留 | 按填写的订阅结束截断模拟 |
| 已到期 | 提示订阅已到期，先保留卡 | 暂停计划 |

核查确认核心原有 `Option<i64>` 与命令层 `clear_sub_end` 分支已覆盖空值。新增独立核心测试模块以遵守文件规模限制，复用原判定矩阵夹具，覆盖四类需求、不同剩余量及库存、无日期时今天来不及重置、清除过期日期后恢复建议、重新填写后恢复计划，以及缺字段和显式 null 的兼容读取。前端冒烟覆盖清空失败回滚、清空成功持久状态、重新读取仍为空、再次填写和日期控件直接清空。

## 2026-11-14 空日期按重置卡有效期规划

按用户后续要求，订阅日期留空时也计算计划。实现采用最后一张已确认有效卡的到期时间为计划截止，所有卡继续按各自的有效期参与供给模拟。订阅日期继续保留空值，输出增加 `planEndAt`、`planEndSource` 与 `daysToPlanEnd`。填写订阅日期时优先使用该日期，空日期时界面提示暂按订阅持续有效计算至卡截止。

计划页与时间轴标明截止来源，依据页展示计划截止和剩余缺口。缺少卡有效期、全部过期、零卡或卡查询失败时暂停卡截止计划并说明原因。已知截止但用量样本不足时提示积累样本。有效期未知的卡继续只展示库存，计划供给使用已确认有效期的卡。

即时建议继续检查最早到期卡。明确需求且当前额度不足、卡早于自然重置到期时建议优先用临期卡；剩余额度够用时保留，能等或暂时不用时保留卡并提示到期风险。临近一小时重置及「今天」截止的规则继续生效。前端每分钟按时钟重算，卡明细变化也会失效缓存，跨过最后一张卡的到期时刻后撤下失效计划。

计划截止、文案与模拟从主模块抽到 `codex_reset_plan.rs`，沿用既有模拟与调用入口。复核发现并修正两处边界，均先复现失败再修复。

- 自然重置恰好在截止时，原文案多算一次，现只统计严格早于截止的恢复事件。
- 模拟中首张卡已过期时，会遮住后续有效临期卡的省卡阈值，现检查当时仍有效的临期卡。

新增核心回归覆盖最晚截止与逐卡失效、手填日期优先、未知/过期/失败库存、清空后的即时临期建议、时间推进与样本不足。前端验证空日期时间轴、重新填写和跨到期时刻的缓存重算。真实账号的兑换与安装包 WebView2 交互仍待验收，本次修改尚未发版。
