# 产品设计 · 首页卡片展示「今日签到」

> 2026-10-21 · 依据 0.1.50 代码实读(`app/src/app.js`、`styles.css`、`index.html`)

## 0. 先说人话

现在「今日有没有签到」只有两个地方能看到:

1. **设置与管理 → 刷新与启动 → 每日签到**(那是一整块设置区,不是日常视野)
2. **胶囊单击速览**(第 3 行一句 `签到 2/4`)

**首页卡片上一个字都没有。** 而首页卡片恰恰是用户唯一天天盯着的地方 ——
于是就出现了 2026-10-20 那个现场:后台早就签到成功(100 分到账),用户看着卡片
却以为没签,还照着一个过期的提示去网页登录,白折腾一轮。

这个设计要解决的就是:**打开挂件一眼就知道今天签了没、领了多少、还有谁没签。**

## 1. 先说清楚:数据早就有了

后端 `checkin_state` 命令已经返回每个渠道的完整状态(`CheckinState`):
`outcome` / `credits` / `attempts` / `nextTryAt` / `canTry` / `needsUser` /
`streakDays` / `monthCredits` / `log`。

前端 `loadCheckin()`(app.js:3989)在**每次刷新时都会跑**(app.js:2229),
`CK` 这张表在首页本来就有全部数据。

**所以这不是"要加数据",是"有了没画"。** 这一点决定了工作量很小:
后端几乎不用动,主要改渲染。

## 2. 展示什么:四态徽标

签到状态有十几种内部 short code(`claimed` / `already` / `retry:ready` /
`retry:device` / `recheck` / `auth` / `no_cred:...` / `shape:...` / `inactive:...` / 空…)。
**但对用户只需四态** —— 其余的细节放 tooltip:

| 态 | 徽标 | 颜色 | 含哪些内部 code | 点击行为 |
|---|---|---|---|---|
| **已签** | `✓ +100` | 绿 `--ok` | `claimed`(带 credits) | 无 |
| **已签** | `✓ 已签` | 绿 `--ok` | `claimed`(无数额)、`already`、`inactive:*` | 无 |
| **可领** | `可领 100` | 蓝 `--ac`(强调) | `retry:ready`、`retry:ready:{活动id}` | **立即领取** |
| **待签** | `待签` | 灰 `--tx3` | 空、`retry:*`、`recheck` | 无 |
| **需处理** | `需登录` | 黄 `--warn` | `auth` | 打开设置(定位到该渠道) |
| **需处理** | `未就绪` | 灰 `--tx3` | `no_cred:*` | 打开设置(定位到该渠道) |
| **需处理** | `异常` | 黄 `--warn` | `shape:*` | 打开设置(定位到该渠道) |

**为什么 `claimed` 与 `already` 的文案不同**(重要,不能合并):

- `claimed` = **我们刚刚替他领到了** → 可以说 `+100 分`
- `already` = **平台说今天已签过**,可能是他自己在客户端点的 → 只能说 `✓ 已签`,
  数额放 tooltip。**绝不能把平台的既有状态说成"我们领到了"** ——
  这是签到那三条红线里的第 2 条(「不把点了按钮说成领到了」)。

### 不显示的条件(必须严格)

以下任一成立就**一个像素都不画**:

- 该渠道没有签到能力(不在 `CHECKIN_ON` 里)
- 签到**没开启**(`enabled === false`)—— 这是关键:默认关,
  没开的人不该看到满屏"待签"
- 渠道被隐藏(`hidden`)
- 正在读状态(`CK[id]` 还没有值)—— **不能先画"待签"再跳成"已签"**

**最后一条尤其重要**:宁可晚 200ms 出现,也不能先给一个假状态。
这个产品已经被"界面显示陈旧结论"坑过一次(0.1.50 那个 5 分钟空窗)。

## 3. 画在哪:沿用 `.wmark` 那套机制

卡片头部当前结构(`app.js:601-612`):

```
[图标] [名称 .nn · 简称 .nsh] [状态点 .dot] [⚠ .wmark]        [余额 .v / 副值 .p] [▶]
```

`.wmark` 是**既有的"极小标记,折叠后仍保留"的先例**(styles.css:388-390):

```css
.wmark{display:none; ...}
body.form-compact .wmark{display:inline}   /* 紧凑条里才显示 */
```

签到徽标**照抄这一套**:命名 `.ckb`,默认隐藏,紧凑条里显示。

位置:**紧跟 `.wmark` 之后**,仍在名称行内。

```
[图标] [名称] [●] [⚠] [✓ +100]                          [余额] [▶]
```

### 三个形态的分级(与产品既有做法一致)

| 形态 | 徽标 | 理由 |
|---|---|---|
| **面板**(主形态) | `.ckb` 常显 | 有一整行宽度,四态都放得下 |
| **紧凑条**(46px 单行) | `.ckb` 常显,但**只对"可领"与"需处理"放大**;已签/待签压到最小字 | 紧凑条是"扫一眼"用的,最该跳出来的是"有件事等你点" |
| **胶囊** | 不改 | 速览第 3 行已有 `签到 N/M`,再塞会撑爆 132–280px |
| **吸附竖条** | 不改 | 只有色块,没有任何数字 |

### 面板形态:展开后的详情区补全信息

主卡片是"一眼",详情才是"看清"。`renderDetail` 里加一块:

```
签到
  ✓ 今日已签 · 平台侧显示已签到
  领到 +100 分 · 连续 7 天 · 本月共 300 分
  上次尝试 23:43 · 下次自动重试 10:00 后
  [ 立即领取 ]  [ 关闭该渠道签到 ]
```

数据全部来自已有的 `CheckinState`,不新增后端字段。

## 4. 交互:徽标可点,但只在有意义时

只有两种态可点,**其余是纯展示**(不做无意义的点击):

- **可领** → 点击 = 立即领取(复用现有 `ckrun` 动作)
- **需处理** → 点击 = 打开设置并展开该渠道卡

已签/待签**不可点** —— 点了什么也不会发生的按钮比没有按钮更糟。

点击后要有反馈:`ckrun` 已在跑时按钮禁用并显示"领取中…"(现有逻辑)。

## 5. 汇总:顶栏一条,只在"还有没签的"时出现

`.sum`(今日/本周/本月消耗)那一行是**钱的领域**,不该混进签到。

建议在 `.list` **顶部**加一条极窄的提示条,**只在存在未签渠道时出现**:

```
今天还有 2 个渠道没签到 · 查看
```

- 全部签完 → 这条**消失**(不留"全部已签"的横幅,那是噪音)
- 签到全关 → 不出现
- 点"查看" → 打开设置到签到区

> **2026-10-23 修订(真机反馈)**:只有一个渠道待签时,汇总数字不足以说明下一步 ——
> 条上改成**渠道名 + 动作**:能自己领就写「Qoder 今天还没签 · 点此领取」(直接领),
> 领不了就写「签到待处理:凭据失效 · 去处理」并落到**渠道卡那一行**(去登录/重试在卡片里);
> 多个渠道才保留「还有 N 个 · 去查看」,且签到区现在会画出每渠道的今日状态与按钮。
> 原来的「点查看 → 设置签到区」只有两个开关,用户看完不知道要做什么。

### ⚠ 这里有两个既有 bug,必须一起修

现在胶囊速览的 `签到 N/M`(`peekCheckinLine`,app.js:1224-1242)是错的:

**bug 1:`already` 不算已签**

```js
if (top && top.day === day && String(top.outcome||"").startsWith("claimed")) done++;
```

只数 `claimed`。而今天 WorkBuddy 的实况是 `already` —— **真实已签,计数却算没签**。
应该 `claimed || already`。

**bug 2:Qoder 的"今天"不是本地日**

`day` 用 `new Date()` 算本地日期,而 **Qoder 的周期日从 10:00 起算**
(`CheckinDef::day_roll_hour = 10`)。所以在 10:00 之前,Qoder 的当前周期日
是**昨天**的日期 → 和本地 `day` 对不上 → 明明签了也显示没签。

**修法(推荐):后端把判断权收回去。**
`CheckinState` 加一个字段 `doneToday: bool`,由后端用 `cycle_day(now, roll_hour)`
+ outcome 算好。前端只数 `doneToday`,**彻底不做日期运算**。

这也符合既有的一条经验:凡是"哪一天"的判断,后端算过就别在前端再算一遍
(0.1.49 那个 `last_auth_version` 就是同一个思路)。

## 6. 边界与异常(这些必须画对)

| 情形 | 徽标 | 说明 |
|---|---|---|
| 凭据失效但仍会重试 | `待签` + tooltip 说"打开一次客户端" | 不报黄 —— 重试会自己好 |
| 凭据失效且已放弃当天 | `需登录` 黄 | `canTry === false` 时才是真的需要人管 |
| 未到跨日时刻(Qoder 10:00 前) | `待签` + tooltip "10:00 后可签" | **文案必须说 10:00,不能说"明天"** |
| 退避中 | `待签` + tooltip "约 8 分钟后再试" | 复用现有 `ckHold()` |
| 本期无活动 | `✓ 已签`(灰绿) + tooltip "本期无打卡活动" | `inactive` 不该显示成"待签",那会让人一直等 |
| 读状态失败 | **不画** | 不知道就别编 |

## 7. 关键裁决(需要拍板)

| # | 问题 | 建议 | 理由 |
|---|---|---|---|
| 1 | 徽标放名称行还是单独一行? | **名称行**(紧随 `.wmark`) | 沿用 `.wmark` 的折叠机制;单独一行会让每个签到渠道多 1 行,面板变高 |
| 2 | 四态够不够? | **够** | 十余种内部 code 对用户只有"签了/能签/等着/要你管"四种意义,其余进 tooltip |
| 3 | `already` 要不要显示数额? | **不显示**,只写 `✓ 已签` | 那条数额不是我们领的,写 `+100` 会让人以为是我们干的 |
| 4 | 顶部要不要汇总条? | **要,但只在有未签时出现** | "还有 2 个没签"是行动提示;"全部已签"是噪音 |
| 5 | 徽标可点吗? | **只在"可领"与"需处理"时可点** | 点了没反应的按钮比没有按钮更糟 |
| 6 | 汇总的前端日期运算怎么处理? | **收进后端**,加 `doneToday` | Qoder 的 10:00 跨日让前端算必错 |
| 7 | 胶囊/吸附形态要不要加? | **不加** | 胶囊第 3 行已有;吸附只有色块 |

## 9. 不做什么(明确排除)

- **不做签到历史图表** —— 那是"设置 → 每日签到"区的事,不该上首页
- **不做手动补签 / 改签到时间** —— 平台侧不接受,做了就是骗人
- **不把签到状态混进余额数字或状态点**(`.dot` / `.v` 的颜色) ——
  这是既有红线:**签到永远不能影响余额渲染**
- **不在胶囊里再加一行** —— 132px 宽放不下,且速览已有
- **不做"预计能领多少"** —— 平台没给就不编

## 10. 验收清单

在真机上逐条确认:

1. 签到关着的渠道 → **卡片上没有任何徽标**
2. 已签(claimed) → `✓ +100`,绿
3. 已签(already) → `✓ 已签`,绿,**没有 "+100"**
4. 可领 → `可领 100`,蓝,**可点**,点完变 `✓ +N`
5. 未到 10:00 的 Qoder → `待签`,tooltip 说"10:00 后可签"(不是"明天")
6. 紧凑条里徽标仍在,且不把行撑高
7. 顶部提示条:有未签才出现,全签完消失
8. 胶囊速览的 `签到 N/M` 与卡片一致(**含 already**,且 Qoder 10:00 前也算对)
9. 把网络断开 → 读状态失败 → 徽标**不出现**(不编造)
