# 额度获取恢复策略（v0.3.17）

请求有效性与数据可展示性分开：`valid` 仍只表示本次取数成功；`stale` 表示额度来自成功历史；`recovery` 传递重试阶段、尝试次数和下一次计划时间。

网络、超时、5xx 和暂时无效的响应允许恢复；明确鉴权失败沿用备用凭据流程；参数和业务错误不做密集重试。普通额度请求每次只访问一个入口，最多首次加 3 次快速重试，间隔 2 / 5 / 15 秒，按渠道加入 0–1 秒错峰。快速恢复预算为首次失败后 60 秒，超出后转入普通恢复阶段。429 遵守 Retry-After（秒或 HTTP 日期）。持续失败退避至 60 / 300 / 900 秒；成功即复位。手动刷新可提前触发，429 等待除外；请求仍共用同一闸门。

后台每秒检查到期渠道；重试不重新获取成功渠道。渠道完成即推送自己的新视图，慢渠道不会阻挡已完成渠道的显示。统一视图在重试阶段使用旧数字与“更新中”，耗尽后使用旧数字与“暂时无法更新”；无成功历史时保留未知状态。明确鉴权失效也允许展示有时间标记的历史额度。

`settings.quota_snapshot_v1:<渠道>` 每渠道只存最近一次成功快照，含额度、周期窗口、积分到期元数据、成功时间和不可逆的凭据范围指纹。不会保存凭据或任意接口错误文本。若凭据提供明确账户 ID，令牌轮换仍可沿用同账户快照；没有账户 ID 时保守按令牌指纹隔离。首次启动且凭据暂时完全无法读取时不恢复无法验证身份的磁盘快照；已有会话可继续使用内存中的历史额度。旧版本的纯数值观测不冒充完整配额窗口。

更换凭据范围不会复用旧账户额度；删除凭据、解除密钥箱引用、删除或重新创建自定义渠道会清除该渠道恢复快照。自定义渠道指纹还包含完整渠道定义，修改单位、路径或接口不会复用旧解释结果。

失败不会改写成功时间，也不会把缓存值作为新快照写入观测表。消耗、积分到账、到账核对与系统额度告警继续以真实成功观测为依据。跨过窗口重置时间后标注“上一周期数据，等待更新”，不推算新周期余额。

验证以本地 HTTP 服务模拟 503 → 成功与 429，检查共享尝试次数、备用入口、快照身份隔离、删除、损坏缓存、无历史重试、跨周期展示与四种形态。需要真实平台凭据的探针保持忽略，不在自动回归中访问用户账户。
