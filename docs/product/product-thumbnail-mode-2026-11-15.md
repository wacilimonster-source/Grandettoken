# 缩略模式产品方案

日期为 2026-11-15。用户已选定窄窗双列缩略，开发规格见 [详细设计](../design/design-thumbnail-mode-2026-11-15.md)。本文保留方案比较记录。

## 目标与现状

在现有单列窗口尺寸内，一屏完整展示本机当前首页的 14 个渠道，用户无需滚动即可识别每个渠道、查看主余额或配额、发现关键异常。底部提供「单列 / 双列 / 缩略」直接选择。

本机首页读取到的渠道依次为 OpenCode Go、Codex、WorkBuddy、Trae、DeepSeek、4SAPI、Hapi、Qoder、Qoder 国内版、WorkBuddy AI、MiniMax、豆包工作、Antigravity、Gemini · Google Cloud。此数量指当前首页展示集合，隐藏渠道与尚未配置渠道需在管理页另行统计。

当前源码的单列内容尺寸为 480×820 逻辑像素，双列为 860×820，另有四周透明边距。字号倍率为 1、1.15、1.3，窗口随倍率调整，并受屏幕工作区钳制。设计尺寸以源码基准为准，不能将截图物理像素当作逻辑尺寸。

## 推荐形态与比较

根据用户补充，推荐采用窄窗内每行 2 个渠道的小卡片网格。480×820 的单列内容窗口容纳 2 列×7 排，共 14 个渠道。每张卡宽约 220px、高 80px，卡间距 8px。

每张卡采用三层信息。

- 顶部为 18px 品牌图标、渠道短名与异常状态点，名称字号建议 12–13px。
- 中间为 22px 主数值，保留分、额度、币种或周窗口标记。
- 底部为 12px 关键状态，单行显示。Codex 显示「5h 59% · 重置卡 3 张」，Antigravity 显示「G5h 1% · 限流 49 分钟」。实际限制的模型组在详情中完整标明，辅助提示也提供完整原文。

WorkBuddy 与 WorkBuddy AI、Qoder 与 Qoder 国内版必须显示不同的名称。Gemini · Google Cloud 可在小卡使用「Gemini · GCP」，完整名称通过辅助提示和详情呈现。金额根据可用宽度使用等宽数字，当前快照的 7,742.08 分与 USD 299.72 均需完整显示。

| 比较点 | 窄窗内每行 2 个渠道 | 纵向双行列表 |
| --- | --- | --- |
| 当前 14 个渠道 | 7 排小卡片 | 14 条摘要行 |
| 主数值 | 可保留 22px 独立数字层 | 约 16px，和名称共用一行 |
| 扫描方式 | 横向读完一排后向下 | 从上至下连续阅读 |
| 辅助说明容量 | 一条短状态 | 可显示较长状态句 |
| 适合用途 | 当前用户的全渠道日常总览 | 偏好连续列表和较长说明的备选 |

推荐将「缩略」固定为窄窗小卡片网格，底栏仍只有用户要求的三种选择。以下纵向列表保留为评审备选。

## 推荐网格的空间预算

| 区域 | 高度预算 |
| --- | --- |
| 顶栏 | 44px |
| 三项摘要及留白 | 64px |
| 渠道数与更新时间 | 24px |
| 7 排卡片，每排 80px | 560px |
| 排间距，6×8px | 48px |
| 网格上下留白 | 16px |
| 底栏 | 40px |
| 合计 | 796px |

基准内容高度 820px 留有 24px 安全空间。渠道从左到右、从上到下遵循现有排序，刷新时保留卡片位置。告警采用固定尺寸的状态点和状态行，避免卡片变高。

## 纵向列表备选

缩略模式采用纵向双行列表。每行占满窗口宽度，14 个渠道按原有顺序连续呈现。通过减少卡片留白、合并重复说明、压缩摘要区获得空间。

每个渠道包含以下内容。

- 左侧 22px 品牌图标，同时提供状态点。
- 第一行展示渠道名称和右对齐主数值，数值保留单位或额度窗口含义。
- 第二行展示一条关键说明，优先放限流、登录失效、数据陈旧、短窗口耗尽或临期情况。
- 正常行使用中性文字。异常同时使用文字和状态色，整行高度保持稳定。
- 渠道名建议 13px，主数值 16px，辅助说明 12px。禁止为塞入更多渠道持续缩小文字。

缩略列表每行默认 44px，双行文案固定行高。行间用细分隔线，渠道行构成一个连续列表。长名称省略，悬停和键盘聚焦可读取全名，详情中始终显示全名。

## 纵向列表的空间预算

以下为标准字号下的设计预算，需要实现后在原生窗口核验。

| 区域 | 高度预算 |
| --- | --- |
| 顶栏 | 44px |
| 三项摘要及其上下留白 | 64px |
| 列表说明行，显示「全部 14 个渠道」及更新时间 | 24px |
| 14 个渠道，每行 44px，含分隔线 | 616px |

| 底栏 | 40px |

480×820 内容窗口剩余 16px 安全空间。摘要改为紧凑三格，保留「临期积分 / 最早到期 / 签到进度」及各自入口。最早到期的渠道名和明细在点击后呈现，摘要中保留日期。渠道级日期仍可显示在列表第二行。

## 渠道信息口径

| 渠道类型或渠道 | 右侧主数值 | 第二行优先内容 |
| --- | --- | --- |
| 积分渠道 | 完整积分与单位 | 最近临期金额与时间，正常时显示签到或到期概况 |
| API 余额渠道 | 金额与币种 | 余额告警、刷新异常，正常时显示今日消耗 |
| Codex | 本周剩余百分比，明确标「周」 | 5 小时剩余百分比与重置卡数量，异常时优先显示耗尽和恢复时间 |
| OpenCode Go | 当前主周期剩余百分比 | 周期重置倒计时 |
| Antigravity | Gemini 本周剩余百分比，明确标「G周」 | Gemini 5 小时余量，以及当前实际限制窗口与恢复时间 |
| Gemini · Google Cloud | 带 USD 的赠金余额 | 到期时间或剩余天数，手填日期来源可在详情读取 |
| 豆包工作 | 上游额度及单位 | 明示到期未知 |

原型中的余额来自查看本机时的页面快照，时长属于当时页面显示。研发须复用现有渠道展示模型、余额口径、数据时效和倒计时计算，渠道名单从运行时生成。

第二行信息优先级为读取失败或登录失效、限流与额度耗尽、临期、其他用量或签到。多个异常同时发生时显示最高优先项及「另有 N 项」，点击查看详情。Codex 的双窗口和 Antigravity 的关键短窗口需有渠道专用布局，不能通过通用省略使其完全消失。

陈旧快照保留旧余额，使用「~」和「数据已旧」标识。读取失败且没有旧快照时显示「读取失败」。真正的零余额显示 0 和单位。刷新期间保留已有行和数值，只更新刷新反馈。

## 操作与底栏

- 底栏左侧提供 AI 优惠入口，中间为「单列 / 双列 / 缩略」三段选择，右侧为设置与更多。退出收进更多菜单，为三段选择留出可点击空间。
- 选中项常亮，点击目标项直接进入对应布局。设置页同步使用三段选择，并记住上次选择。
- 单列与缩略共享同一窄窗尺寸，二者切换时窗口保持位置。双列按现有规则进入宽窗，返回缩略时恢复窄窗并执行屏幕边界钳制。
- 点击任意渠道打开现有详情底部弹层。弹层中展示完整说明、历史、逐笔到期及操作。关闭后恢复原列表位置与焦点。
- 列表行不做原位展开，避免详情把后续渠道挤出首屏。
- 首次加入此功能时延续用户当前模式，由用户点击缩略后保存选择。
- 保存模式失败时回滚选择与窗口尺寸，并显示用户可见提示。

## 数量增加与屏幕约束

推荐网格在 14 个渠道时使用 7 排×80px。新增至 15 或 16 个渠道时使用 8 排，将卡片高度收紧至 68px，共需 788px，包含前述顶栏、摘要、间距和底栏预算。超过 16 个渠道时允许网格滚动，并继续显示总数。

大字号沿用现有窗口倍率，屏幕工作区钳制后须重新核算可用高度。当前本机 14 个渠道全部一屏可见是实施验收条件，实际字号与屏幕缩放需实测。以下行高规则仅用于纵向列表备选。

按实际可用高度计算行高，默认 44px，最多收紧到 38px。标准 820px 内容高度按上述预算可容纳 16 行，每行 38px，共 796px。

本次验收必须覆盖当前 14 个渠道全部一屏显示。新增至 15 或 16 个渠道时在允许范围内降低行高，文字大小保持可读。超过容量时列表允许滚动，底栏与摘要固定，列表说明行明确展示总数。更高数量若仍要求一屏全显，需要单独评审新的信息密度方案。

大字号随现有窗口倍率调整。遇到屏幕高度钳制，先按实际高度计算行高，达到 38px 后允许滚动。对当前机器应记录真实字号、工作区、scaleFactor 和最终窗口尺寸，再确认 14 行均可见。

## 实现边界

增加第三个 panelLayout 值及独立缩略布局模块和样式，复用现有渠道列表、排序、筛选、详情和状态数据。接线与窗口尺寸映射保留在既有入口，大段渲染逻辑放入新模块。独立模块纳入 IPC 和静默失败扫描。实施阶段再同步 DESIGN.md 中的已实现规范。

## 验收条件

1. 本机当前 14 个首页渠道，在同一字号的单列尺寸窗口内，进入缩略后全部完整可见，最后一行与底栏均无裁切。
2. 14 个渠道的名称与主数值均可辨识，WorkBuddy 与 WorkBuddy AI、Qoder 与 Qoder 国内版能清楚区分。
3. Codex 的周与 5 小时额度、Antigravity 的周余额与短窗口限制能同时理解。
4. 长金额、不同币种、零余额、读取失败、旧快照、限流、临期、到期未知均有可读结果。
5. 刷新、倒计时变化、失败恢复和签到状态变化不会改变行高或推挤后续渠道。
6. 三档字号、深浅主题以及屏幕钳制分别核验。三种布局切换、重启恢复、保存失败回滚和详情焦点恢复分别核验。
7. 回归夹具的渠道名单从后端定义与运行时列表提取，检查遗漏、重复和最后一行可见。注入漏行或扩大行高的坏样本时断言必须失败。
