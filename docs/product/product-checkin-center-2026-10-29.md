# 产品设计 · 签到中心(独立页签)

> 2026-10-29 · 依据 0.1.70 代码实读(`app/src/app.js`、`app/src/index.html`、`app/src-tauri/src/lib.rs`、`app/core/src/store.rs`)

## 0. 先说人话

现场:用户在首页顶部看到「签到」格,点它想看"今天哪些签了、哪些没签、历史记录",
落点却是**设置 → 刷新与启动**页签里的一段设置区(`openManage() + showTab("run") + 滚到 #ckSet`,
app.js:2969)。用户的原话是"点击以后到的是设置" —— 落点和意图错位了。

能看的信息其实**有**,但分散且浅:

| 想看的 | 现在在哪 | 差距 |
|---|---|---|
| 今天哪些签了 / 没签 | 设置 → 刷新与启动 → 活动监测与签到(每渠道状态行);渠道卡签到行 | 埋在设置页里;首页签到格只有汇总 `2/3` + 分段条,无逐渠道明细 |
| 签到记录 | 同上,近 7 天一行小字(`s.log.slice(0,7)`,app.js:5472) | 只有 7 天;一行点分隔的小字,没法扫"哪天没签" |
| 累计 | "本月已领 X 分"一句 desc | 没有趋势、没有连续天数(除 Qoder 平台自报) |

**关键事实:数据库里躺着 400 天全量流水。** `checkin_log` 表每次签到都记
(`record_checkin`,store.rs:1355),清理策略留 90+310=400 天(store.rs:1163)。
但 `checkin_state` 只回传近 7 天(lib.rs:2642 `now - 7*86_400`),前端再砍成 7 条。
**这不是"没数据",是"有数据没出口"。**

## 1. 方案:管理窗口新增「签到」页签,首页签到格改落这里

页签栏(现有 6 个)加一个,排在「渠道」之后:

```
渠道 · 签到 · 模型 · 显示 · 刷新与启动 · 密钥箱 · 关于
data-p="ck"
```

**为什么是页签,不是首页内嵌或独立弹窗:**

- 首页面板 380px 宽、三级折叠,放不下日历和流水表;首页的职责是"一眼知道状态",
  不是"翻记录"。
- 独立弹窗要新开窗口基建;管理窗口的页签机制(`showTab`,app.js:3209)是现成的,
  「模型」页已是先例 —— 一个功能长到设置区装不下,就升级成页签。
- 顺带给「刷新与启动」减负:那个页签现在塞了取数频率 / 开机更新 / 签到 / 显示 /
  快捷键五段,签到区(活动总览 + 每渠道 4 行)是里面最大的一块。

**首页入口的点击矩阵(职责要分开:格子 = 看,提示条 = 办):**

| 入口 | 行为 |
|---|---|
| 首页顶部「签到」格(`ckstripopen`,无待办语义) | 打开管理窗口,落「签到」页签(一律,不再滚到 run 的区块) |
| 首页待签提示条,单渠道 | **不变**:落该渠道卡并展开(2026-10-23 的行为,那是"去处理") |
| 首页待签提示条,多渠道 | 落「签到」页签,今日区置顶可操作 |
| 徽标上的「领积分」(`ckrun`) | **不变**:就地领取,不跳页 |

`run` 页签里的「活动监测与签到」整块(开关 + 状态 + 流水)搬进新页签;
`index.html:224-226` 的标题与说明随之移走。

## 2. 页签内容(从上到下)

### ① 今日总览条(常驻一行)

```
今天 ✓ 2/3 · 本月已领 310 分        [Trae✓][WorkBuddy✓][Qoder·]
```

- 左:进度 + 本月合计(已有 `month_credits`);右侧沿用 `ckseg` 分段条样式,
  每段一个渠道,点分段落该渠道行。
- 三态着色:全签完绿 / 有可领蓝(强调) / 有需处理黄。"完成"和"坏了"不能长得一样(D09)。

### ② 今日逐渠道行(能操作)

复用渠道卡那套 `ckRowHtml` 四态,**没签的排前面**:

| 态 | 来源 code | 动作 |
|---|---|---|
| 已签 ✓(+N / 平台已签) | `claimed` / `already` | 无(数额差异的口径见红线②) |
| 可领 | `retry:ready*` | 领积分(与设置页同一个 `ckRun`) |
| 待签 / 确认中 | 空、`retry:*`、`recheck` | 显示下次尝试时间 |
| 需处理 | `auth` / `no_cred:*` / `shape:*` | 去登录(跳渠道卡) |

### ③ 近 30 天日历(每渠道一条横带)

```
Trae      ▪▪▪▪▪▪▪▪▪▪▪▪▪▪▪▪▪▪▪▪▪▪▪▪░▪▉   30 天 · 领到 28 · 漏 1
WorkBuddy ▪▪▪▪▪▪▪▪▪▪▪▪▪▪▪▪▪▪▪▪▪▪▪▪▪▪▪   30 天 · 领到 29
```

- **横带 30 格滚动窗口**(以今天结尾),不用自然月历:签到是滚动习惯,
  月历月初总有大片空格造成"全没签"的误读,翻页还多一步。
- 格子五色:**领到**(实心绿,tooltip +N 分) / **平台已签**(空心绿) /
  **没签**(灰) / **失败或需处理**(黄) / **无数据**(虚线更浅)。
- 悬停 tooltip:日期、结果、数额、尝试次数(`attempts`)。
- "无数据"与"没签"必须分开 —— 开启签到之前的日期没有记录,画成"没签"
  是把没发生的事说成失败了。

### ④ 明细流水表(近 90 天)

- 列:时间 / 渠道 / 结果 / 数额 / 原因。倒序,渠道筛选 chips。
- `detail` 字段(失败原因)收在可展开行里,默认只露一句摘要;
  失败行用警示色。`retry:*` 一天多条是正常的(节拍器每小时试),流水表如实全列,
  日历带只取当天**最后一行**(与 `checkin_of_day` 判"今天处理过了吗"同一口径)。

### ⑤ 管理区(从 run 页签搬来)

每渠道两个开关(活动监测 / 自动领取)+ 免责文案(data-why="checkin" 原样保留)。

## 3. 不变的红线(全部沿用,一条不新增)

1. **不把 `already` 说成"领到了"** —— 平台既有状态与我们代领必须两个文案;
   数额只在 `claimed` 时出现在正文,`already` 的数额进 tooltip。
2. **数额只信平台字段**,拿不到不编("平台未返回数额")。
3. **签到态绝不参与余额渲染** —— 签到页签坏了,余额该是什么还是什么。
4. **日期口径全部后端算**:Qoder 周期日 10:00 起算(`day_roll_hour`),日历带的
   "哪格是哪天"由后端按周期日给,前端零日期运算(0.1.5x 那两个跨日 bug 的教训)。
5. **没开签到的人一个像素不多画**:所有渠道都关时**整个页签隐藏**
   (开启入口在渠道卡里,那里本来就有开关);页签栏少一项比一个空页签干净,
   与"不该提醒一件用户没要求的事"同一原则。

## 4. 数据与改动清单

**后端(一个新命令,既有查询全复用):**

- 新增 `checkin_history { days }`:
  - 每渠道按天聚合行(day → 当日最后一行的 outcome / credits / attempts,
    `recent_checkins` 已有,窗口从 7 天放开到 90 天,LIMIT 400 够 3 渠道 × 90 天);
  - 每天补"无记录"的空槽:**开启日之后**的无记录天 = `missed`,之前 = `no_data`
    (开启时间配置里已有 `attempts` 首次时间可参照,或新增 `enabled_since`);
  - 汇总:本月已领(复用 `checkin_month_credits`)、30 天领到/漏天数。
- `checkin_state` 不动 —— 首页轮询还走它,7 天窗口对徽标够用。

**前端:**

- `index.html`:页签按钮 + `data-p="ck"` 面板骨架;`run` 页签删除签到块。
- `app.js`:`renderCheckinCenter()`(总览 + 今日行 + 日历带 + 流水表 + 管理区);
  `ckstripopen` 两处(app.js:2969、3035)改落 `showTab("ck")`;
  `checkin-updated` 事件到达时若页签开着则重渲染。

## 5. 分期

- **P0(一次可发版)**:新页签 + 今日总览/逐渠道行 + 90 天流水表 + 首页入口改对。
  后端只加 `checkin_history`。用户问的三件事("哪些签了、没签、记录")当轮就闭环。
- **P1**:30 天日历带 + 汇总统计(领到/漏天数)。
- **不做**:导出 CSV(无场景)、签到提醒设置(节拍器 + 一日一次的提示条已覆盖)、
  跨渠道合并日历(渠道日roll口径不同,合并必错)。
