# Grandettoken 0.3.30 — 托盘不再闪 · 全量代码排查修复 23 项缺陷

本版包含两部分:**请求数据时托盘与胶囊不再闪**,以及对 PC 端全部代码
(app.js 约 9000 行 + Rust 后端约 8500 行)一次全量排查出的 **23 个 bug 的修复**。

## 请求数据时托盘与胶囊不再闪

- 托盘绿底在每轮取数时变灰、数字变白的根因已修:以前每轮请求发起前,后端会把缓存快照临时置为「失联 + 更新中」推给界面,托盘/胶囊/渠道卡先闪一次失败态,取完再回绿。现在请求期间不发任何过场状态,四种形态都保持上一次成功后的画面。
- 数字与颜色只在这一轮真正取到数之后更新;取数失败仍走原有口径(行内提示「正在获取 · 自动重试中」/「暂时无法更新」),不受本次改动影响。
- 自定义渠道同口径处理:请求发起不再发布过场视图,结果回来才更新。
- 内置与自定义渠道的会话保持、重试节奏、快照落库逻辑均保持不变。

## 全量排查修复(重点几条)

- **自定义渠道不再丢**:以前添加自定义渠道后,改任意设置(主题 / 间隔 / 快捷键 / 隐藏渠道……)都会把它整份删掉、密钥留在凭据管理器成孤儿;删掉的渠道也会在下一次改设置时"复活"。根因是设置保存整份覆盖配置时漏保护自定义渠道字段,现在该字段只由添加 / 删除命令改动。
- **自定义渠道的「复制 / 显示密钥」可用**:以前点击必报「未知渠道」,尾号也永远空着;现在与内置渠道同一套放行口径。
- **修复一个理论死锁**:到账核对单处理时锁序与「检查更新」相反,交错时可能把挂件整体冻死(无提示、不自愈)。已按全局锁序约定拆开嵌套。
- **配置写入全部收进串行闸**:签到失败记录、WorkBuddy 复登、更新检查时间戳、客户端口径学习等 6 处绕闸的整份写,曾把用户在落库窗口里改的设置倒回旧值。
- **底栏计数与行内状态对齐**:黄色预警渠道不再被算成「正常」,跌破红线的不再标成黄色「预警」。
- **Qoder 签到「去登录」指引修正**:凭据失效时以前让你去打开 Trae(毫无作用),现在指到 Qoder 桌面端。
- **本地 API 网关更稳**:加 60 秒读空闲超时,上游挂起不再永久悬挂连接;上游 4xx/5xx 的错误详情原样透传(截 400 字)并转发 Retry-After;无鉴权本机模式校验 Host,DNS rebinding 不再能读模型列表;网关初始化失败不再让整个应用起不来。

其余细节:详情弹层重取「最近变动」失败不再清掉已有缓存;模型「N 个可用」不再把 0 误报成全部模型数;配额窗口百分比跟随「用掉还是剩余」口径;临期柱状图与合计口径对齐(按自然日),晚间不再漏柱;「最先到期」今天到期的如实写「今天」;签到徽标「10:00 后可签」按北京时间判断;一次 Esc 只关最上面一层;签到状态 / 历史读失败不再装「没有待签」或永远「正在读取」,保留旧值并给重试;启动事件监听提前到首轮取数之前,首检红线预警音不再丢;凭据库读失败如实报错,不再吞成「还没填密钥」;节拍器不再把互斥拒绝记成流水、双计退避;昨日遗留的活动状态不再绕过当天门控;自定义渠道编号分配原子化;配置损坏时体检降级不外呼;手动「立即发布」补配置损坏闸;断开 GitHub 先存「已断开」再删凭据。

余额口径、签到判定、加密同步、自动更新链路本次**未做任何行为改动**。
