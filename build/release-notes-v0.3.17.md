# Grandettoken 0.3.17 — 额度断联重试与历史数据兜底

- 额度请求遇到临时断网、超时或服务端故障时，先在后台重试 3 次，间隔为 2、5、15 秒并带轻微错峰；备用入口与这 4 次尝试共用计数。连续失败后按渠道逐步退避至 1、5、15 分钟。
- 重试期间继续展示最近一次成功额度，标记“更新中”和快照年龄；重试耗尽后仍保留历史值，并提示“暂时无法更新”。面板、紧凑条、胶囊和托盘保持一致。
- 成功额度快照持久化保存，重启后验证当前凭据范围即可恢复历史数据；换账户、换密钥或删除凭据时隔离旧数据。跨过重置时间会明确标注上一周期数据。
- 网络故障不再误报“需登录”；明确鉴权失败才提示处理凭据。限流响应遵守 Retry-After，手动刷新也不会绕过限流等待。
- 内置与自定义渠道都支持历史额度兜底。历史值不作为新观测写入，不生成虚假的消耗或到账记录。

验证：核心测试 423 项通过（9 项按设计忽略），前端冒烟 169/169，通过两个 Rust crate 的全目标编译、CSS 形态守卫和脚本语法检查。
