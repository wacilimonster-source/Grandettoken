## 胶囊「圆角 + 矩形」根因与修复(已改 styles.css,未重编)

用户截图里胶囊同时出现圆角描边和直角底色。逐像素量用户截图:
暗色矩形 245×56 物理像素 == 窗口 200×46 @DPR1.25(即整窗);胶囊描边半径 ≈28 物理 px
== 46/2 是标准胶囊;矩形填充色与胶囊内部**完全一致**;窗口外桌面正常透出(transparent 生效)。

根因:**CSS 背景传播**。`html` 无背景 → 根元素 background-color 为 transparent 且
background-image 为 none 时,body 的 background 被提升到根画布绘制;画布恒为整窗矩形,
不吃 border-radius;而 border / 圆角 / box-shadow 不参与传播,仍画在 body 上 → 两者同框。
面板(12)与紧凑条(10)其实也一直没生效,只是半径小 + 深色桌面看不出来。

修复(方案 A,用户确认):`html{background:linear-gradient(transparent,transparent)}`
—— 只要 html 的 background-image 不是 none,传播即被阻断。同时删掉 `body.form-pill` 的
`backdrop-filter:blur(8px)`(透明窗口里采不到桌面,纯空转),填充 `#12141aee` → `#12141af2`。
位置:`app/src/styles.css` 第 12 行后 + 形态 3 段落。**尚未 cargo build,exe 里还是旧 CSS。**

## 事故:反复强杀 + 重启把 WebView2 搞崩(重要教训)

**现象**:应用启动弹 `msedgewebview2 has stopped working / Error launching CrashSender.exe`。

**根因是我**:为验证反复 `taskkill -F` 掉 tokenscope.exe 又立刻重启,并一度让两个实例
共用同一个 user-data-dir(`%LOCALAPPDATA%\com.wacil.tokenscope\EBWebView`)。
崩溃报告 `EBWebView/Crashpad/watson_metadata` 里三份 dmp(02:09/02:10/02:12)全部写着
`WV=tokenscope.exe`、`ProcessType=browser`、`SubCode=0x80000003`(STATUS_BREAKPOINT,
即 CHECK 失败)—— 时间点与我那几次启动一一对应。用户 01:54 还能正常跑,之后才开始崩。

**教训**:
1. 验证 Tauri + WebView2 应用时,**不要反复强杀 + 立刻重启**;杀之前先等 WebView2 子进程
   自然退出,且**绝不允许两个实例同时跑**(会抢同一个 user-data-dir)。
2. `launch-debug.ps1` 在本机(有代理工具的环境)会挂:PowerShell 5.1 的 `Start-Process`
   遇到 `http_proxy` 与 `HTTP_PROXY` 这种大小写重名变量会抛「已添加项」。
   绕法:先 `[Environment]::SetEnvironmentVariable($n,$null,'Process')` 清掉重名再启动。
3. `WEBVIEW2_ADDITIONAL_BROWSER_ARGUMENTS=--remote-debugging-port=9222` 在这台机器上
   **起不来 CDP 端口**(152/153 运行时都不行),`verify-form.js` 那套 CDP 验证当前不可用。
4. 工具调用结束时,**调用内启动的 GUI 进程会被回收** —— 想「启动 + 截图」必须在同一次
   调用里做完。
5. 屏幕截图(mss/BitBlt)**拍不到透明分层窗口**:挂件位置只会拍到它后面的窗口内容,
   不能据此判断「没渲染」。窗口是否真的在画,应查子窗口类名
   (`WRY_WEBVIEW` / `Chrome_WidgetWin_0/1` / `Chrome_RenderWidgetHostHWND`)与
   WebView2 进程数,而不是看截图。

**已做的清理**:杀掉全部 tokenscope 及其名下 4 个 msedgewebview2 子进程(只按
`com.wacil.tokenscope` 这个 user-data-dir 匹配,未碰其它应用);把持久化配置里的
`form` 从 `pill` 还原成 `panel`;确认无残留进程。3 份 dmp 共 26MB 留在
`EBWebView/Crashpad/reports/`,待用户决定是否删除。
