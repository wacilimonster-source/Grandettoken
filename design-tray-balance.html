一、物理约束:先说清楚能做到什么程度

  • Windows 托盘(通知区)只接受位图图标,没有 macOS 菜单栏那种文字模式 —— 「显示余额」只能把数字画进图标;
  • 图标实际显示尺寸只有 16~24px(随 DPI 缩放),经验上限是 2~3 个粗体字符;¥74.20 这种完整金额放不下,必须缩写;
  • 缩写必然丢精度:「74」看不出是 74.2 还是 74.9。所以定位是概览数字,看详情仍靠 tooltip / 胶囊。

四、数字缩写规则(与界面口径一致)

  • 金额型:<¥100 取整「74」;<¥1万 一位小数千缩写「1.2k」;更大「2.4w」(中文习惯用万);
  • 配额型:直接是百分比数「82」(最紧张窗口,与胶囊同口径);
  • 积分型:同金额缩写规则「6.1k」;取整后仍超过 3 字符才升一档;
  • 底色 = 状态色(绿/黄/红/灰),数字永远白色粗体 + 深色描边保证任意底色可读;
  • 隐藏渠道跟随现有 hiddenChannels:被隐藏的渠道不参与托盘轮播。

五、设置项(新增一个开关)

托盘图标显示余额数字数字为概览缩写;关闭则回到状态角点样式。跟随胶囊轮播,悬停看完整金额

六、实现要点(确认后动代码)

  • 现有 drawTrayIcon() 已是 canvas 32×32 → set_tray_icon IPC,只换画法:底色由「渐变+角点」改为「状态色整底」,中央绘制缩写数字;
  • 缩写函数前端新增 trayAbbr(v),与 points/money 并列;轮播节奏复用 PILL 的 5s 定时器,零新增计时器;

  • Rust 侧零改动(图标字节流协议不变)。
